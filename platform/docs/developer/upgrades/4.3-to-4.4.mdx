## Update Gems

Run the following command to update your gems to 4.4:

```bash
bundle update
```

to install the new gems.

## Remove gems merged into PallasTrade Core

These gems were merged into PallasTrade Core in version 4.4. All of their functionality is now included in the `pallastrade` gem so you can remove them.

### (Optional) Remove PallasTrade Digital

If you used that gem in the past you need to remove it. Digital products are now incorporated into PallasTrade core and you cannot use that gem anymore.

1. Remove `pallastrade_digital` from your `Gemfile`

### (Optional) Remove PallasTrade Wishlist

If you used that gem in the past you need to remove it. Wishlists are now incorporated into PallasTrade core and you cannot use that gem anymore.

1. Remove `pallastrade_wishlist` from your `Gemfile`
2. (Optional) Remove `//= require pallastrade/frontend/pallastrade_wishlist` from `vendor/assets/javascripts/pallastrade/frontend/all.js`
3. (Optional) Remove `*= require pallastrade/frontend/pallastrade_wishlist` from `vendor/assets/stylesheets/pallastrade/frontend/all.css`

## Update gems

```bash
bundle update
```

## Install missing migrations

```bash
bin/rake pallastrade:install:migrations
```

## Run migrations

```bash
bin/rails db:migrate
```

## Run install generators

This will copy some files from `pallastrade_backend` to your application.

```bash
bin/rails g pallastrade:backend:install
```

If you're using `pallastrade_frontend` you need to run the frontend install generator as well:

```bash
bin/rails g pallastrade:frontend:install
```

## Additional fixes and hints

### Make sure that Node is available in your cloud environment

On Heroku, you need to add the node buildpack - [https://devcenter.heroku.com/articles/buildpacks#using-multiple-buildpacks](https://devcenter.heroku.com/articles/buildpacks#using-multiple-buildpacks)

### Add PallasTrade ActiveJob queues to your Sidekiq config

PallasTrade uses ActiveJob for processing long running operations to not interrupt your web server performance.

If you're using [Sidekiq](https://github.com/mperham/sidekiq) you need to update your `config/sidekiq.yml` file and 2 new queues:

* `pallastrade_stock_location_stock_items`
* `pallastrade_webhooks`

### Disabling webhooks

PallasTrade 4.4 introduces webhook events for most of the PallasTrade resources (Products, Orders, Customers, etc). If you wish to disable this globally you can set the environment variable:

```bash
DISABLE_PALLASTRADE_WEBHOOKS=true
```

If you would like to disable firing webhooks for certain elements of your application you can wrap these methods in a block:

```ruby
PallasTrade::Webhooks.disable_webhooks do
  ... run your code here ...
end
```

Webhooks do not fire on touch events. Webhooks also do not do anything until there is a first webhook subscriber created which can be done in the Admin Dashboard or via Platform API.

### Update PallasTrade Dependencies that was renamed

Please change in your codebase:

```ruby
PallasTrade::Dependencies.account_update_address_service
```

to

```ruby
PallasTrade::Dependencies.address_update_service
```
