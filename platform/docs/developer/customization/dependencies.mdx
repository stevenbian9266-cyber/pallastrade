## Overview

With Dependencies, you can replace PallasTrade services, CanCanCan abilities, and
API v3 serializers with application-specific implementations.

## Application (global) customization

This will change every aspect of the application (both APIs, Admin Panel, and Storefront).

In your `config/initializers/pallastrade.rb` file, you can set the following:

```ruby
PallasTrade.cart_add_item_service = MyAddToCartService
```

or using the block syntax:

```ruby
PallasTrade.dependencies do |dependencies|
  dependencies.cart_add_item_service = MyAddToCartService
end
```

Now let's create your custom service.

```bash
mkdir -p app/services && touch app/services/my_add_to_cart_service.rb
```

And add the following code to it:

```ruby
class MyAddToCartService < PallasTrade::Cart::AddItem
  def call(order:, variant:, quantity: nil, metadata: {}, options: {})
    ApplicationRecord.transaction do
      run :add_to_line_item
      run PallasTrade.cart_recalculate_service
      run :update_in_external_system
    end
  end

  private

  def update_in_external_system(new_order_line_item)
    # Your custom logic here
  end
end
```

This code will:

1. Inherit from `PallasTrade::Cart::AddItem`
2. Override the `call` method to add your custom logic
3. Call `run :add_to_line_item` to add the item to the cart
4. Call `run PallasTrade.cart_recalculate_service` to recalculate the cart (returns the resolved class)
5. Call `run :update_in_external_system` to execute your custom logic, eg. updating Order in an external system such as ERP

## Using dependencies in your code

When you need to use a dependency in your code, you can access it directly via the `PallasTrade` module:

```ruby
# Returns the resolved class (not a string)
PallasTrade.cart_add_item_service.call(order: order, variant: variant, quantity: 1)

# For API dependencies, use the PallasTrade.api accessor
PallasTrade.api.cart_serializer
```

## Controller level customization

To customize one endpoint without changing the global serializer, decorate its API v3
controller and override `serializer_class`:

```ruby
module PallasTrade::Api::V3::Store
  module CartsControllerDecorator
    def serializer_class
      MyNewAwesomeCartSerializer
    end
  end

  CartsController.prepend(CartsControllerDecorator)
end
```

Business services are shared across Store API, Admin API, jobs, and application code.
Override their core dependency (for example `PallasTrade.cart_add_item_service`)
instead of creating a second API-specific service setting. Controller-specific
behavior can call a custom service directly from a decorator.

The available API serializer injection points are defined in
`backend/pallastrade_gems/pallastrade_api-5.6.0.rc1/lib/pallastrade/api/dependencies.rb`.

## API level customization

Store and Admin API v3 serializers have separate injection points. Store serializers
use an unprefixed resource name; Admin serializers use the `admin_` prefix:

```ruby
PallasTrade.api.cart_serializer = MyNewAwesomeCartSerializer
PallasTrade.api.admin_product_serializer = MyNewAwesomeAdminProductSerializer
```

A Store serializer change affects Store API responses. Admin serializers normally
extend their Store counterparts, while an explicit `admin_*` override remains
admin-only. Service overrides continue to use the global `PallasTrade.<name>`
accessor because both API surfaces share the same business logic.

## Debugging dependencies

PallasTrade provides rake tasks to help you debug and inspect dependencies:

### List all dependencies

```bash
bin/rake pallastrade:dependencies:list
```

This will output all dependencies with their current values:

```
[CORE]
cart_add_item_service           PallasTrade::Cart::AddItem
cart_create_service             PallasTrade::Cart::Create
cart_recalculate_service        PallasTrade::Cart::Recalculate [OVERRIDDEN]
...

[API]
cart_serializer                 PallasTrade::Api::V3::CartSerializer
admin_product_serializer        MyApp::AdminProductSerializer [OVERRIDDEN]
...
```

You can use `grep` to filter results:

```bash
bin/rake pallastrade:dependencies:list | grep cart
```

### Show only overridden dependencies

```bash
bin/rake pallastrade:dependencies:overrides
```

This shows only the dependencies that have been customized, along with their original and current values:

```
[Core OVERRIDES]
cart_recalculate_service  PallasTrade::Cart::Recalculate -> MyApp::CartRecalculate (config/initializers/pallastrade.rb:15)

[API OVERRIDES]
admin_product_serializer  PallasTrade::Api::V3::Admin::ProductSerializer -> MyApp::AdminProductSerializer (config/initializers/pallastrade.rb:20)
```

### Validate all dependencies

```bash
bin/rake pallastrade:dependencies:validate
```

This validates that all dependencies can be resolved to valid classes. If any dependency points to a non-existent class, it will report an error:

```
..........F.........
1 invalid dependencies:
  [Core] cart_add_item_service: uninitialized constant NonExistentClass
```

## Programmatic introspection

You can also inspect dependencies programmatically:

```ruby
# Check all current values
PallasTrade::Dependencies.current_values
# => [{name: :cart_add_item_service, current: MyApp::CartAddItem, default: 'PallasTrade::Cart::AddItem', overridden: true}, ...]

# Check if a specific dependency is overridden
PallasTrade::Dependencies.overridden?(:cart_add_item_service)
# => true

# Get override information (where it was set)
PallasTrade::Dependencies.override_info(:cart_add_item_service)
# => {value: MyApp::CartAddItem, source: "config/initializers/pallastrade.rb:15", set_at: 2024-01-15 10:30:00}

# Validate all dependencies resolve to valid classes
PallasTrade::Dependencies.validate!
# => true (or raises PallasTrade::DependencyError)
```

## Backwards compatibility

The legacy string-based syntax is still supported for backwards compatibility:

```ruby
# Legacy syntax (still works)
PallasTrade::Dependencies.cart_add_item_service = 'MyAddToCartService'
result = PallasTrade::Dependencies.cart_add_item_service.constantize

# New syntax (recommended)
PallasTrade.cart_add_item_service = MyAddToCartService
result = PallasTrade.cart_add_item_service
```

Both syntaxes can coexist, but the new syntax is recommended as it's more concise and provides better error messages at assignment time.

## Default values

Default values can be easily checked by:

1. Using the rake task: `bin/rake pallastrade:dependencies:list`
2. Looking at the source code:
   * Application dependencies: `backend/pallastrade_gems/pallastrade_core-5.6.0.rc1/lib/pallastrade/core/dependencies.rb`
   * API v3 dependencies: `backend/pallastrade_gems/pallastrade_api-5.6.0.rc1/lib/pallastrade/api/dependencies.rb`
