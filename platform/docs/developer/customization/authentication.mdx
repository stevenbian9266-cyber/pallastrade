If you installed PallasTrade following the [Quickstart guide](/developer/quickstart), you can completely skip this step - you are all set and integrated with the [Devise](https://github.com/plataformatec/devise) gem.

However if you're adding PallasTrade to an existing application that has its own authentication system, you will need to follow these steps.

## Using Devise

If you're currently using [Devise](https://github.com/plataformatec/devise) for authentication, you can follow the steps below to integrate PallasTrade with your existing authentication system.

Firstly set your `User` class as `PallasTrade.user_class` in your `config/initializers/pallastrade.rb` file:

```ruby
PallasTrade.user_class = 'User'
```

Now, run the generator to set up PallasTrade integration with Devise:

<CodeGroup>

```bash PallasTrade CLI (Docker)
pallastrade generate pallastrade:authentication:devise
```

```bash Without PallasTrade CLI
bin/rails g pallastrade:authentication:devise
```

</CodeGroup>

This will create a new file in `lib/pallastrade/authentication_helpers.rb` that serves as a bridge between PallasTrade and your existing authentication system routes. You can then use this file to customize the routes to your liking. It should automatically pick up standard Devise routes.

Secondly, this generator will add necessary modules to your `User` model.

```ruby
# app/models/user.rb
class User < ApplicationRecord
  # ... your existing code ...

  include PallasTrade::UserAddress
  include PallasTrade::UserMethods
  include PallasTrade::UserPaymentSource
end
```

This will ensure that your `User` model can be used as a PallasTrade user.

This generator will also add 2 new lines to your PallasTrade initializer file:

```ruby
Devise.parent_controller = "PallasTrade::BaseController"
Devise.parent_mailer = "PallasTrade::BaseMailer"
```

This ensures that Devise will use PallasTrade storefront layout for login/signup/etc and use PallasTrade mailer layout for sending emails so they'll match your Storefront branding.

If you have more complex setup, you can remove these lines and customize the routes and mailer in your own initializer file.

## Using Custom Authentication

If you're using a custom authentication system, you can follow the steps below to integrate PallasTrade with your existing authentication system.

Firstly set your `User` class as `PallasTrade.user_class` in your `config/initializers/pallastrade.rb` file:

```ruby
PallasTrade.user_class = 'User'
```

Now, run the generator to set up PallasTrade integration with your custom authentication system:

<CodeGroup>

```bash PallasTrade CLI (Docker)
pallastrade generate pallastrade:authentication:custom
```

```bash Without PallasTrade CLI
bin/rails g pallastrade:authentication:custom
```

</CodeGroup>

This will create a new file in `lib/pallastrade/authentication_helpers.rb` that serves as a bridge between PallasTrade and your existing authentication system routes. You will need to customize this file to fit your needs.

Secondly, this generator will add necessary modules to your `User` model.

```ruby
# app/models/user.rb
class User < ApplicationRecord
  # ... your existing code ...

  include PallasTrade::UserAddress
  include PallasTrade::UserMethods
  include PallasTrade::UserPaymentSource
end
```
