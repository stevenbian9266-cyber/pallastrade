## Overview

Secure application design, implementation, deployment, and operations are all
required for a production store. PallasTrade builds on Ruby on Rails security
defaults, but each operator remains responsible for securely configuring and
maintaining their deployment. See the
[Rails Security Guide](https://guides.rubyonrails.org/security.html).

## Supported Versions

The following versions are actively maintained and receive security patches.

| Version | End of life |
| ------- | ----------- |
| 5.x     | 26.03.2027  |
| 4.10    | 06.09.2026  |

Versions that are not listed above do not receive security patches. Use the
[upgrade guides](../upgrades/) for older installations.

## Reporting Security Issues

Do not report security vulnerabilities through public GitHub issues,
discussions, or pull requests. Email
[stevenbian9266@gmail.com](mailto:stevenbian9266@gmail.com) with:

- the vulnerability type and affected version;
- reproducible steps and proof of concept, if available;
- the expected impact;
- whether AI tools were used to prepare the report.

Reports must be manually verified. PallasTrade does not operate a bug-bounty
program and does not promise monetary rewards.

The maintainer will triage the report privately, prepare and test a fix, and
publish release and advisory information when appropriate. External patches
and pull requests are not accepted, including for security fixes.

### Security Advisories

Published advisories are available through the repository's
[GitHub Security Advisories](https://github.com/stevenbian9266-cyber/pallastrade/security/advisories).

## Security Best Practices

Recommended controls include:

- keep PallasTrade and all dependencies up to date;
- follow the Rails Security Guide;
- scan Ruby dependencies with
  [bundler-audit](https://github.com/rubysec/bundler-audit);
- run [Brakeman](https://github.com/presidentbeef/brakeman) in CI;
- keep credentials outside source control and rotate them when exposure is
  suspected.
