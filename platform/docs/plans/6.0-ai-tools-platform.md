# AI Tools Platform and Provider Management

**Status:** Draft
**Target:** PallasTrade 6.0
**Depends on:** `6.0-admin-api.md`, `6.0-admin-spa.md`, `5.5-admin-api-key-scopes.md`
**Last updated:** 2026-07-24

## Summary

为 PallasTrade 建立一个面向业务工具场景的通用 AI 基础设施。首批预置 DeepSeek 和 OpenAI（GPT）两类模型供应商，管理员可以在管理后台配置供应商、API Key、模型、关键参数和启停状态；未来的翻译、报告分析、商品文案、客服辅助、数据归类等业务场景通过统一的 Capability Registry 和 Gateway 接入，不直接依赖任何供应商 SDK。

本计划只建设 AI Provider 管理、模型管理、凭据安全、统一调用网关、任务运行记录、权限、管理后台和扩展契约，不实现自动翻译、AI 分析报告或其他具体业务能力。后续业务能力作为独立 capability 接入本平台。

## Goals

1. 在管理后台提供独立的“AI 工具”菜单和完整管理模块。
2. 预置 DeepSeek、OpenAI 两种 Provider，允许后续注册其他云模型或自部署模型。
3. 支持在后台录入或替换 API Key、Base URL、Project ID、超时、重试、并发和模型默认参数。
4. 支持系统、商店、Provider、模型和 Capability 多级开关。
5. 任意一级关闭时，在发起外部 HTTP 请求之前终止调用；默认不静默切换其他模型。
6. 为后续业务场景提供稳定、可测试、与供应商无关的 Ruby 接口。
7. 所有调用具备商店隔离、权限校验、审计、Token/费用统计、错误分类和可观测性。
8. 复用当前 Rails、PostgreSQL、Redis、Sidekiq、ActiveStorage、CanCanCan、Admin API v3、事件和 Dashboard 架构。

## Non-goals

本计划不包含：

- 自动翻译的提示词、界面和写入流程。
- AI 分析报告的指标定义、提示词和报告模板。
- 面向消费者的聊天机器人。
- RAG、向量数据库、Embedding 管道或知识库。
- 让模型直接执行 SQL、任意 Ruby 代码或未经批准的 Tool Calls。
- 图片、音频和视频生成。
- Provider 计费充值、API Key 代购或密钥托管服务。
- 单独部署 AI 微服务。
- 将现有仓库顶层 `ai/` 目录改造成运行时模块；该目录继续只存放 Agent Skills、Hooks 和开发辅助内容。

## Current Architecture Fit

当前项目已经具备以下可复用能力：

- Rails 8.1 后端统一使用 Active Job + Sidekiq。
- Redis 已作为后台任务和运行时基础设施。
- `PallasTrade::Integration` 已提供 store-scoped STI、`active` 开关、集成注册和 `can_connect?` 连接验证语义。
- `PallasTrade::PermissionSets` + CanCanCan 已提供后端权限边界。
- Admin API v3 已提供 JWT/API Key 鉴权、scope、prefixed ID、错误 envelope 和 store scope。
- React Dashboard 已提供导航、路由、权限、表格、表单、TanStack Query 和插件注册。
- 旧 Rails Admin 仍是当前兼容管理面；React Dashboard 是 6.0 的目标管理面。
- `PallasTrade::Event`、Subscriber 和 Webhook 已提供异步副作用及生命周期通知。
- ActiveStorage 私有存储可承载未来 capability 生成的大型 artifact。
- Sentry、Lograge 和 Sidekiq Web 已可用于错误定位与任务运维。

因此 AI 模块采用模块化单体和独立 Rails Engine，不引入新的部署单元、数据库或消息中间件。

## Key Decisions (do not deviate without discussion)

1. **AI 运行时是独立扩展，不进入 `pallastrade_core`。** 新建 `pallastrade_ai` Rails Engine，由主应用通过本地 gem 引用。Core 只提供扩展所需的通用 Integration、权限、事件和队列契约。
2. **不使用顶层 `ai/` 目录。** 该目录属于开发 Agent 能力，与线上业务运行时严格分离。
3. **业务只能调用 Capability/Gateway，不能直接调用 Provider。** 任何业务代码出现 `DeepSeekClient`、`OpenAIClient` 或供应商 URL 都视为架构违规。
4. **复用 `PallasTrade::Integration` 管理 Provider。** DeepSeek 和 OpenAI 分别是 store-scoped Integration STI 类型，一个商店默认只能配置一个同类型 Provider account。
5. **API Key 不存入 Integration `preferences`。** 现有 preferences 适合非敏感参数，不保证密文存储。Provider secret 使用独立模型和 Active Record Encryption，且未配置加密主密钥时 fail closed。
6. **密钥只写不读。** 后台和 API 永不返回完整 API Key；保存后只返回 `configured`、掩码 hint 和最后轮换时间。管理员只能替换或清除。
7. **模型是独立持久化资源。** Provider 负责凭据和连接参数，Model Configuration 负责远端 model ID、启停、能力声明和默认生成参数。
8. **Capability 是代码注册表，不是用户自由创建的 Prompt。** 业务开发者在代码中注册 capability；管理员只能启停、选择模型和调整允许暴露的参数，不能通过后台创建任意可执行 Prompt。
9. **五级开关全部 fail closed。** 系统 kill switch、商店总开关、Provider 开关、Model 开关、Capability 开关任意一级关闭，都不允许网络请求。
10. **关闭模型不触发静默 fallback。** 如果 capability 选定模型被关闭，该 capability 立即变为 unavailable。只有管理员显式配置并开启 fallback 后才允许切换，并记录实际使用模型。
11. **配置页的“测试连接”不等于启用。** 管理员可以在 Provider 关闭时测试凭据；测试成功不会自动开启 Provider 或模型。
12. **统一网关同时支持同步和异步。** 低延迟交互能力可以同步调用；批量或长任务使用 Sidekiq。两种路径都创建相同的 `AiRun` 审计记录。
13. **Provider 协议不强行统一成 OpenAI SDK。** DeepSeek 使用其 OpenAI-compatible Chat Completions 协议；OpenAI 首选 Responses API。二者在 Adapter 层归一，不把某个供应商的请求结构泄漏给 capability。
14. **结构化输出必须做本地 Schema 校验。** Provider 返回合法 JSON 不代表符合业务契约。Capability 必须声明 output schema，Gateway 在成功前完成解析和验证。
15. **模型不直接访问数据库。** 未来 capability 由 Rails 代码准备经过授权、裁剪和脱敏的输入；模型不能自行生成并执行 SQL。
16. **Provider price 只用于估算。** 每个 run 保存定价快照和估算费用，供应商账单仍是最终依据。
17. **配置和调用均以 Store 为隔离边界。** 不允许从默认商店配置回退到其他商店；跨商店共享 Provider 账户不在第一版范围内。
18. **所有 Provider HTTP 调用显式声明 Faraday 依赖。** 不依赖其他 gem 偶然带入的传递依赖。
19. **CI 不调用真实模型。** Provider contract、Faraday test adapter 和 Fake Provider 覆盖全部自动化测试。
20. **管理界面先保证当前 Rails Admin 可用，同时以 React Dashboard 为 6.0 完整实现。** 两个界面复用同一 service/API，不各自实现 Provider 调用逻辑。

## Terminology

| Term | Meaning |
|---|---|
| Provider | 外部模型供应商账户，例如一个商店配置的 DeepSeek 或 OpenAI Integration |
| Model | Provider 下可供业务选择的远端模型配置，例如 `deepseek-v4-flash` |
| Capability | 代码注册的业务型 AI 能力，例如未来的 `catalog.translate` |
| Capability Setting | 某商店对一个 capability 的启停、主模型、fallback 和参数覆盖 |
| Gateway | 所有业务调用 AI 的唯一入口 |
| Run | 一次同步、异步、失败或被开关拦截的调用记录 |
| Artifact | Run 产生的结构化结果或大型文件 |
| Provider Catalog | 扩展代码中维护的 Provider 类型和推荐模型清单 |

## Provider Design

### Provider Registry

Provider 类型通过代码注册，而不是让管理员输入任意 Ruby class：

```ruby
PallasTrade::AI.providers.register(
  :deepseek,
  integration_class: 'PallasTrade::AI::Integrations::DeepSeek',
  adapter_class: 'PallasTrade::AI::Providers::DeepSeek',
  catalog_class: 'PallasTrade::AI::Catalogs::DeepSeek'
)
```

每个 Provider 声明：

- 稳定 key 和显示名称。
- Integration STI class。
- Adapter class。
- 官方默认 Base URL。
- 可编辑的非敏感设置及类型。
- 需要的 secret 字段。
- 连接测试策略。
- 推荐模型目录。
- 支持的输入模态和功能。
- 支持的 canonical parameters。
- 默认超时与可重试错误。

没有注册的 Provider type 不能由 API 创建，避免任意 class constantization。

### Preset Providers

#### DeepSeek

预置非敏感设置：

- `base_url`，默认 `https://api.deepseek.com`。
- `open_timeout_seconds`。
- `read_timeout_seconds`。
- `max_retries`。
- `concurrency_limit`。
- 可选代理/网关标识，但不直接接受任意代理凭据。

Secret：

- `api_key`。

2026-07-24 的初始模型目录：

- `deepseek-v4-flash`：默认高吞吐/常规工具模型。
- `deepseek-v4-pro`：默认高质量/复杂推理模型。

旧 `deepseek-chat`、`deepseek-reasoner` 不进入新安装的 preset catalog。若已有配置导入旧名称，后台标记 deprecated 并要求管理员迁移，不自动替换。

#### OpenAI

后台显示名为“OpenAI（GPT）”。

预置非敏感设置：

- `base_url`，默认 `https://api.openai.com/v1`。
- 可选 `organization_id`。
- 可选 `project_id`。
- `open_timeout_seconds`。
- `read_timeout_seconds`。
- `max_retries`。
- `concurrency_limit`。
- `store_responses`，默认关闭，Adapter 仅在 API 支持时映射。

Secret：

- `api_key`。

2026-07-24 的初始模型目录：

- `gpt-5.6-sol`：复杂、质量优先的工作。
- `gpt-5.6-terra`：质量、延迟、费用平衡。
- `gpt-5.6-luna`：高吞吐、成本敏感任务。

OpenAI Adapter 首选 Responses API。模型目录是可升级的代码数据，数据库只保存管理员实际选择和修改过的配置；升级 catalog 不覆盖管理员开关或参数。

### Custom Models

管理员可以在已配置的 Provider 下增加“自定义模型”，但只能填写：

- 管理后台显示名称。
- 远端 `model_id`。
- 模型类别。
- 支持能力声明。
- 允许的默认参数。

自定义模型仍使用该 Provider 的 Adapter、Base URL 和凭据，不能通过模型记录指定任意 Adapter class。

自定义 OpenAI-compatible Provider 不在第一阶段范围内；后续通过注册新的 Provider type 实现，不能用修改 DeepSeek Base URL 的方式冒充无限制通用代理。

## Credential Security

### Storage

新建 `PallasTrade::AI::ProviderSecret`，与 Provider Integration 一对一：

```text
pallastrade_ai_provider_secrets
  id
  integration_id        unique, FK -> pallastrade_integrations
  credentials           encrypted text/JSON
  key_hint              non-secret, e.g. "sk-...7H2K"
  encryption_key_version
  rotated_at
  created_at
  updated_at
```

`credentials` 使用 Active Record Encryption 的非确定性加密。数据库、备份和 console SQL 只能看到 ciphertext。

强制要求：

- AI 模块启用时，web 和 worker 必须配置相同的 Active Record Encryption keys。
- 缺失 encryption primary key 时禁止创建、更新或使用 Provider secret。
- 不允许像部分旧模型一样在未配置 encryption 时退化为明文。
- encryption keys 只来自部署 Secret Manager/环境，不提交仓库。
- 提供 key version，为将来的密钥轮换和后台重加密留出空间。

### API Semantics

Provider API 永远只返回：

```json
{
  "credential_configured": true,
  "credential_hint": "sk-...7H2K",
  "credential_rotated_at": "2026-07-24T10:00:00Z"
}
```

规则：

- Create 时允许提交 API Key。
- Update 未传 `api_key` 或传空白时保留原 Key。
- Replace 明确更新 secret、hint、rotated_at，并使旧连接验证状态失效。
- Clear 是独立、需确认的操作；清除后自动关闭 Provider 的有效可用性。
- API、Rails logs、Sentry breadcrumbs、Active Job 参数中不得出现 plaintext key。
- `filter_parameters` 至少覆盖 `api_key`、`access_token`、`credential`、`credentials`、`secret`、`authorization`。
- Key 不进入 Sidekiq job payload；worker 执行时根据 provider prefixed ID 从数据库解密读取。

### Connection Test

连接测试建模为 nested resource：

```text
POST /api/v3/admin/ai/providers/:provider_id/connection_tests
```

行为：

1. 授权 `manage` Provider。
2. 从数据库读取并解密 secret。
3. 校验 Base URL 安全策略。
4. 调用 Provider 的低成本/非生成型验证接口；必要时才使用最小生成请求。
5. 记录 `last_verified_at`、`verification_status`、规范化错误码和安全化错误摘要。
6. 不保存供应商响应正文。
7. 不改变 Provider/Model 的 active 状态。

错误仅暴露可操作信息，例如 `invalid_credentials`、`model_access_denied`、`timeout`、`rate_limited`，不回显原始 Authorization header 或完整上游 body。

## Model Configuration

### Data Shape

`PallasTrade::AI::Model` 表示一个商店可选的远端模型：

```text
pallastrade_ai_models
  id
  store_id                  FK, required
  provider_id               FK -> pallastrade_integrations, required
  name                      admin display name
  provider_model_id         remote model string
  kind                      text | multimodal | embedding | image | audio
  active                    default false
  built_in                  catalog preset or custom
  catalog_version
  capabilities              JSONB metadata
  default_parameters        JSONB
  position
  created_at
  updated_at
```

约束：

- unique `(provider_id, provider_model_id)`。
- Provider 必须属于同一 store。
- 删除 Provider 时 model 配置受限删除或级联软停用，不能留下可路由模型。
- `active` 只表示模型自身开关；最终 availability 仍受其他级别控制。
- catalog 更新新增 preset，不自动打开。
- 管理员已编辑的参数不被 catalog 更新覆盖。

### Canonical Parameters

Gateway 只识别一组供应商无关参数：

- `max_output_tokens`
- `temperature`
- `reasoning_effort`
- `thinking`
- `response_format`
- `stream`
- `timeout_seconds`
- `stop`
- `seed`（仅 Provider 声明支持时）

参数合并优先级：

```text
Provider defaults
  < Model defaults
  < CapabilitySetting overrides
  < Invocation overrides allowed by capability
```

Adapter 必须：

- 将 canonical parameter 映射为上游字段。
- 拒绝 Provider 不支持的字段，不能静默透传。
- 对互斥字段做本地验证。
- 将实际使用参数的安全子集写入 Run。

Capability 可以锁定某些参数。例如一个严格 JSON capability 可以禁止管理员关闭 `response_format`，但允许管理员调整 `max_output_tokens`。

## Switch and Availability Semantics

### Five Gates

1. **System kill switch**
   - 环境变量 `PALLASTRADE_AI_ENABLED=false`。
   - 面向运维，用于事故或合规紧急关闭。
   - 后台只读显示“系统已关闭”，不能通过 UI 覆盖。

2. **Store AI switch**
   - `PallasTrade::AI::Setting#active`。
   - 管理员在 AI 概览页控制该商店的总开关。

3. **Provider switch**
   - 复用 `PallasTrade::Integration#active`。
   - 关闭后，该 Provider 下所有模型均不可用，但保留各模型自己的 active 状态。

4. **Model switch**
   - `PallasTrade::AI::Model#active`。
   - 关闭后，所有映射到该模型的 capability 不再发起外部请求。

5. **Capability switch**
   - `PallasTrade::AI::CapabilitySetting#active`。
   - 关闭单个业务场景，不影响其他场景。

### Resolution Matrix

| System | Store | Provider | Model | Capability | Result |
|---|---|---|---|---|---|
| off | any | any | any | any | `system_disabled`，无 HTTP |
| on | off | any | any | any | `store_disabled`，无 HTTP |
| on | on | off | any | on | `provider_disabled`，无 HTTP |
| on | on | on | off | on | `model_disabled`，无 HTTP |
| on | on | on | on | off | `capability_disabled`，无 HTTP |
| on | on | on | on | on | 继续凭据、预算、权限和 schema 校验 |

其他不可用原因：

- `credentials_missing`
- `credentials_unreadable`
- `configuration_invalid`
- `model_not_configured`
- `budget_exceeded`
- `concurrency_exceeded`
- `permission_denied`
- `input_invalid`

### No Silent Fallback

第一版默认：

- Capability 的 primary model 不可用时直接返回 unavailable。
- 不按 Provider、价格或模型目录自动选择“相近模型”。
- 不因为 DeepSeek 失败就将数据发给 OpenAI，反之亦然。

未来允许管理员为 capability 显式选择一个 fallback model，并打开 `fallback_enabled`。Fallback 必须：

- 与 primary 一样通过五级开关和权限检查。
- 在 UI 明确展示目标 Provider。
- 在 Run 记录 fallback reason 和实际 Provider/model。
- 对跨 Provider fallback 显示数据出境/隐私提示。

## Capability Extension Contract

### Registry

未来业务场景通过代码注册：

```ruby
PallasTrade::AI.capabilities.register(
  'catalog.example',
  handler: 'PallasTrade::AI::Capabilities::CatalogExample',
  input_schema: 'PallasTrade::AI::Schemas::CatalogExampleInput',
  output_schema: 'PallasTrade::AI::Schemas::CatalogExampleOutput',
  authorization: {
    action: :update,
    subject: 'PallasTrade::Product'
  },
  execution: :async,
  allowed_parameters: %i[max_output_tokens reasoning_effort],
  required_model_capabilities: %i[text structured_output]
)
```

本计划不注册任何生产 capability。可提供一个仅测试环境加载的 `test.echo` capability，用于 contract spec，不出现在生产后台。

### Capability Responsibilities

每个未来 capability 必须负责：

- 稳定 `key` 和版本。
- 输入 schema。
- 输出 schema。
- 从已授权业务资源构造输入。
- 数据最小化和脱敏。
- Prompt 模板和 prompt version。
- 同步/异步模式。
- 所需模型能力。
- 允许管理员覆盖的参数白名单。
- 业务资源权限。
- 结果如何被业务显式应用。

Capability 不负责：

- 读取 API Key。
- 选择未配置的 Provider。
- 自己实现 HTTP/retry。
- 绕过开关。
- 直接记录敏感日志。
- 直接调度 Sidekiq queue name。

### Gateway API

同步调用：

```ruby
result = PallasTrade::AI::Gateway.call(
  capability: 'catalog.example',
  store: PallasTrade::Current.store,
  actor: current_admin_user,
  input: input,
  resource: product
)
```

异步调用：

```ruby
run = PallasTrade::AI::Gateway.enqueue(
  capability: 'catalog.example',
  store: PallasTrade::Current.store,
  actor: current_admin_user,
  input: input,
  resource: product
)
```

统一返回类型：

- `Success`：包含 run 和校验后的结果。
- `Queued`：包含 run。
- `Unavailable`：包含稳定 reason code，不发起 HTTP。
- `Rejected`：权限、输入或预算拒绝。
- `Failure`：已发起执行但 Provider 或 output validation 失败。

业务 UI 可以先调用：

```ruby
PallasTrade::AI.available?(
  capability: 'catalog.example',
  store: current_store,
  actor: current_admin_user,
  resource: product
)
```

该方法无副作用、不创建 Run、不访问 Provider，仅返回 availability 和 reason。

## HTTP Client and Network Policy

使用 Faraday，`pallastrade_ai.gemspec` 显式声明版本约束。统一 middleware：

- JSON encode/decode。
- Authorization header 注入。
- Open/read/write timeout。
- request ID。
- 有限重试。
- 日志脱敏。
- metrics instrumentation。
- response size limit。

重试范围：

- 网络连接失败。
- 408。
- 429，并遵守 `Retry-After`。
- 明确可重试的 5xx。

不重试：

- 400 schema/parameter error。
- 401/403。
- 内容安全拒绝。
- 本地 output validation failure超过一次修复尝试。
- 余额或配额硬限制。

Base URL 安全：

- Preset Provider 默认 URL 由 catalog 锁定。
- 高级覆盖仅对 `AIConfigurationManagement` 开放。
- 只允许 HTTPS。
- 拒绝 loopback、link-local、metadata IP 和私网地址。
- DNS 解析后再次校验目标地址，防止 DNS rebinding。
- 生产环境可配置 egress allowlist。
- Redirect 默认关闭；若开启，只允许同 host。

## Background Jobs

新增队列：

```yaml
- [pallastrade_ai_interactive, 3]
- [pallastrade_ai_batch, 1]
```

Engine 配置：

```ruby
PallasTrade::AI.queues.interactive = :pallastrade_ai_interactive
PallasTrade::AI.queues.batch = :pallastrade_ai_batch
```

Jobs：

- `PallasTrade::AI::ExecuteRunJob`
- `PallasTrade::AI::ExpireRunsJob`
- `PallasTrade::AI::AggregateUsageJob`

约束：

- Job 参数只包含 run prefixed ID。
- Worker 重新读取当前开关；排队后被关闭的任务转为 `skipped`，不调用上游。
- Provider 调用前原子地将 queued 转为 running。
- 已 succeeded/failed/cancelled/skipped 的 run 不重复执行。
- Provider 成功但数据库写入超时时，通过 idempotency key 和 provider request ID 做恢复判断。
- Retry 只适用于幂等、明确可安全重放的 run。
- 并发限制按 store + provider 维度使用 Redis semaphore。

## Data Protection

Capability 注册时必须声明数据分类：

```text
public
internal
personal
sensitive
payment_restricted
```

默认策略：

- `payment_restricted` 禁止发送给任何 Provider。
- `sensitive` 默认禁止，需 capability 和商店政策双重允许。
- `personal` 必须最小化并使用隐私标识，不发送邮箱、电话、地址作为 provider user identifier。
- Provider-specific privacy identifier 使用不可逆的 store/user hash。
- Capability 负责去除不需要的字段。
- 跨 Provider fallback 被视为新的数据处理目的，必须显式开启。

未来若增加数据驻留或供应商区域 endpoint，作为 Provider policy 实现，不放进业务 capability。

## Cost and Budget Controls

Gateway 在调用前检查：

1. store daily request limit。
2. store daily token limit。
3. store daily estimated cost limit。
4. capability-specific limit。
5. provider concurrency。

预算达到时返回 `ai_budget_exceeded`，不访问外部网络。

费用估算：

- Provider catalog 带版本化 pricing metadata。
- Run 在完成时保存本次 pricing snapshot。
- catalog 价格更新不改写历史 Run。
- 未知自定义模型可以只记录 Token，不展示费用或使用管理员提供的估算价格。
- UI 明确注明“估算费用，以 Provider 账单为准”。

## Provider Catalog Upgrades

Catalog 由代码版本控制，包含：

- provider key。
- recommended models。
- deprecated model IDs。
- capability flags。
- supported parameters。
- pricing metadata 和 effective date。

升级流程：

1. 新增 catalog model 不自动创建 active model。
2. 已有 catalog model 的显示元数据可刷新。
3. 不覆盖管理员修改的 active、参数、名称和 capability 映射。
4. deprecated model 在 UI 告警，但不自动关闭。
5. removed model 仍保留历史 Run 和数据库配置，路由前给出不可用/迁移提示。
6. Provider 实际返回的 model ID 写入 Run，以识别 alias 路由变化。

## Acceptance Criteria

### Configuration

- [ ] 管理后台存在独立“AI 工具”菜单。
- [ ] DeepSeek 和 OpenAI 作为预置 Provider 显示。
- [ ] 管理员可以保存、替换、清除 Key，但不能读取已保存完整 Key。
- [ ] 管理员可以编辑受控关键参数和测试连接。
- [ ] 管理员可以增加/编辑/开关模型。
- [ ] 管理员可以控制商店 AI 总开关。

### Disable Guarantees

- [ ] system、store、Provider、model、capability 任一级关闭均不发生外部 HTTP。
- [ ] 关闭 model 后，依赖场景返回稳定 unavailable reason。
- [ ] 默认不自动调用其他模型。
- [ ] 排队任务执行前重新检查开关。

### Extensibility

- [ ] 业务 capability 不引用 Provider class、SDK、URL 或 Key。
- [ ] 新 Provider 可通过 registry + adapter + catalog + contract specs 接入。
- [ ] 新 capability 可通过 registry 自动进入后台配置页面。
- [ ] 同一 capability 可以由管理员选择 DeepSeek 或 GPT 模型。

### Security

- [ ] Key 经过强制加密，未配置 encryption key 时 fail closed。
- [ ] Key 不出现在 API、logs、Sentry、Sidekiq、fixtures。
- [ ] Provider/Model/Run 全部 store scoped。
- [ ] connection test 和 Base URL 通过 SSRF 防护。
- [ ] capability invocation 同时检查 AI 和领域权限。

### Operations

- [ ] Run 记录实际 Provider/model、Token、延迟、错误和估算费用。
- [ ] 有清晰的 429、5xx、timeout、invalid credentials 错误分类。
- [ ] 交互和批量队列隔离。
- [ ] CI 无真实 Provider 调用。
- [ ] 可通过环境 kill switch 紧急关闭所有 AI 请求。

## Constraints on Current Work

在本计划实施完成前：

- 不要在业务 service、controller、job 或 frontend 中直接调用 DeepSeek/OpenAI。
- 不要把 Provider Key 加入 `backend/.env.example` 的示例值、Store metadata、Integration preferences 或 Dashboard 环境变量。
- 不要复用顶层 `ai/` 目录放运行时代码。
- 不要为第一个业务场景先造临时 client；先完成 Gateway 和 Provider contract。
- 不要在后台提供自由 Prompt 或任意 Base URL 执行能力。
- 不要把 DeepSeek 的 OpenAI-compatible 协议误认为所有 Provider 的长期统一 API。
- 不要在 model 关闭时自动选择另一个 Provider。
- 不要在 React Dashboard 中绕过 Admin API 直接访问模型供应商。
- 不要把 API Key 发送到浏览器可读响应、localStorage 或 `VITE_*` 变量。
- 不要把 AI availability 只做成前端按钮隐藏；后端 Gateway 必须强制执行。
- 新业务场景必须声明 capability key、schema、权限、数据分类和执行模式。

## Open Questions

1. React Dashboard 是否作为首次发布唯一完整界面，还是 Legacy Admin 与 Dashboard 同期完整交付？本计划默认两者同期交付，Dashboard 为长期主界面。
2. 第一版是否允许同一 Store 配置多个 OpenAI/DeepSeek account？本计划默认每种 Provider 一个账户；多账户需放弃现有 Integration `(store, type)` 唯一语义。
3. 是否在第一版实现显式 fallback？本计划保留数据模型但默认关闭；可以先只实现 unavailable。
4. `content_logging_mode=encrypted` 是否首版交付？最安全的首版可以只支持 `none` 和 `metadata`。
5. 预算限制使用美元统一估算，还是支持 Provider 原币？建议内部保存 provider currency + amount，Dashboard 按原币展示，暂不做汇率换算。
6. 是否允许 Admin API Key 自动轮换 Provider secret？本计划默认只允许 JWT staff session。
7. Legacy Admin 在 6.0 后保留多长时间？这决定 Rails Admin AI 页面何时停止扩展。
