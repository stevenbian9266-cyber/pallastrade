## 需求标题

FIN-P4-1：支付资金事实解析（Financial Fact Resolution）——在建立 Immutable Financial Journal 前，统一 Payment/Capture/Refund 的真实金融事实语义。

## 任务类型

新功能（只读语义解析层，无 DB/API/资金副作用变更）

## 需求描述

基于 FIN-P4-0 审计结论：`Payment.completed` 在不同路径下（Stripe auto/manual capture、PaymentCombination、StoreCredit/Check offline、legacy Adyen/PayPal）并不统一等价「PSP cash captured」。在写 Journal 前，先建只读 FinancialFact Resolver 层：`FinancialFact` Value Object（CONFIRMED/AUTHORIZED_ONLY/UNPAID/AMBIGUOUS/NOT_APPLICABLE/UNSUPPORTED；CASH_CAPTURED/STORE_CREDIT_APPLIED/OFFLINE_PAYMENT_RECORDED/REFUND_SUCCEEDED/NONE）、`FinancialInstrumentClassifier`（PSP_CASH/STORE_CREDIT/OFFLINE/UNKNOWN）、`CaptureEvidencePolicy`（禁裸 `payment.completed?`）、`OwnershipResolver`（Payment/Refund → CommerceTransaction 的可靠推导，禁 PSP reference 推断）、`FinancialFacts::ResolvePayment`/`ResolveRefund`（只读、幂等、支持 1 txn N payment facts / multiple refunds / short payment / AMBIGUOUS 不猜）。输出冻结的 Fact contract 供 FIN-P4-2 Journal posting 唯一消费。

## 影响范围（harness affected 输出）

- 变更路径：`backend/pallastrade_gems/pallastrade_core/**`（models + services）+ `backend/spec/**`（新增 5 个 spec）+ 文档（skills/PRD）。全部在 gate allow 范围内。
- 不改动：Payment/PaymentSession/Refund/PaymentCombination/PaymentSplit/CommerceTransaction 既有行为、state machine、DB schema、API、storefront、platform。

## 技术方案（初步）

按 core gem 服务层惯例（`PallasTrade::Transactions::*` / `PallasTrade::Payments::*`）新增：

```text
backend/pallastrade_gems/pallastrade_core/app/models/pallastrade/financial_fact.rb        # Value Object（非 AR，无表）
backend/pallastrade_gems/pallastrade_core/app/services/pallastrade/financial_facts/
  instrument_classifier.rb     # PaymentMethod → PSP_CASH/STORE_CREDIT/OFFLINE/UNKNOWN
  capture_evidence_policy.rb   # 冻结 per-instrument captured predicate（禁裸 completed?）
  ownership_resolver.rb        # Payment/Refund → commerce_transaction 可靠推导
  resolve_payment.rb           # 编排：classify → ownership → amount/currency → evidence → FinancialFact
  resolve_refund.rb            # 同上 for Refund
```

- `FinancialFact` 用 struct/Data-like value object（只读、无 AR），字段见 PRD FR-4P1-01。
- Provider 差异收敛到 `CaptureEvidencePolicy` 内 per-instrument 分支；Stripe 判定基于 PaymentCaptureEvent + capture 状态；Adyen/PayPal 无可靠 captured predicate → AMBIGUOUS/UNSUPPORTED。
- **只读边界**：所有服务不得 create/update/delete 任何 AR 记录、不得调用 purchase/capture/refund/credit。

## 风险点

- 最高风险：capture 判定过宽（把 authorization 当 captured）→ 用 CaptureEvidencePolicy 冻结证据组合 + manual-capture 真实路径测试兜底（PRD §8）。
- 中风险：ownership 误判（把 PSP ref 当 txn）→ OwnershipResolver 只走关联路径，禁 ref 推断 + AC-4P1-16。
- 回滚难度：低（纯新增文件，不改既有行为；删除即可回滚）。
