## 需求描述

为「客户端所见 quote」提供服务端比对护栏，闭环 P1-2/3 的 DEFERRED 409 语义：

1. **Start 比对**（quote 作用域内，仅 quote-active 标准流订单）：`ensure_fresh_quote` 过期路径先 Refresh（既有逻辑）后，若调用方提供 `expected_version`/`expected_price_version` 且与 `order.checkout_version`/`order.price_version` 任一不匹配 → `failure({code:'checkout_version_conflict', message:, details:{order_id, latest:{version, price_version, expires_at, amount_due, display_amount_due}}})`，不建会话。
2. **可选参数**：`PaymentSessions::Start.call(order:, payment_method:, external_data:, expected_version: nil, expected_price_version: nil)`——不提供则行为与 P1-3 完全一致（无 quote/legacy/completed 直通不变；幂等/reuse/operation_key 不变）。
3. **API**：`orders/payment_sessions_controller#create` permit 顶层 `expected_version`/`expected_price_version`（integer/string）并传给 Start；`error_handler` 结构化分支新增 code→status 映射 `checkout_version_conflict → :conflict(409)`；details 透传既有机制。
4. **compact latest quote 来源**：order 权威列（checkout_version/price_version/checkout_expires_at iso8601/amount_due/display_amount_due to_s），无需新查询/新端点。

范围锁：不改 Snapshot/409 触发后客户端流程（P1-4 后续）；不改 legacy/carts 域；不做 auto 拒绝之外的强制刷新；不加表。

## 技术方案（初步）

```ruby
# start.rb ensure_fresh_quote 之后、readiness 之前（quote_active 内）：
if quote_active?(order)
  ...existing refresh/readiness...
  if expected_version.present? && order.checkout_version != expected_version.to_i ||
     expected_price_version.present? && order.price_version != expected_price_version
    latest = { version: order.checkout_version, price_version: order.price_version,
               expires_at: order.checkout_expires_at&.iso8601,
               amount_due: order.amount_due.to_s, display_amount_due: order.display_amount_due }
    return failure(order, { code: 'checkout_version_conflict',
                            message: 'Checkout quote changed; please confirm the updated summary',
                            details: { order_id: order.prefixed_id, latest: latest } })
  end
end
```

controller：`params.permit(PallasTrade::PermittedAttributes.payment_session_attributes + [:expected_version, :expected_price_version])`（或显式 permit）→ `Start.call(..., expected_version: permitted[:expected_version], expected_price_version: permitted[:expected_price_version])`。

error_handler：结构化 Hash 分支新增：
```ruby
STATUS_BY_CODE = { 'checkout_version_conflict' => :conflict }
status = STATUS_BY_CODE.fetch(error[:code], status)
render_error(code: error[:code], message: error[:message], status: status, details: extra.presence)
```

## 风险点

- Refresh 后比对：过期→Refresh 续期；若价格/内容真的变了 → 409（客户端重确认）；若未变 → 放行。existing start_spec（无 expected）不受影响。
- legacy/completed/无 quote 订单：不进入比对分支，行为不变。
- permit 不引入未知列冲突（payment_session_attributes 未知键会被 permit 静默过滤——需显式允许新增两键）。
