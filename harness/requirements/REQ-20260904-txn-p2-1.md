## 需求标题

新增 `CommerceTransaction`/`TransactionOrder` 数据层（TXN-P2-1），为 P0/P1 之上的 durable 交易编排提供模型、状态机、不可变快照与审计事件底座；**不改既有支付/checkout 行为，不新增 API/前端**。

## 任务类型

新功能（Transaction Core 数据层，feature）

## 需求描述

系统目前缺少"一次商业交易"的持久化生命周期（TXN-P2-0 §1）。本包建立两张新表与模型：

- `pallastrade_commerce_transactions`（`txn_`）：state/purpose/quote 绑定（checkout_version/price_version/snapshot_fingerprint）/`snapshot_data`(jsonb, immutable)/amount/currency/payment_combination_id(可空)/时间戳/recovery_attempts/last_error_*；
- `pallastrade_transaction_orders`：transaction↔order 参与者（role/amount_snapshot/completion_status；唯一 `[transaction_id, order_id]`）。

状态机：`created→payment_pending→payment_confirmed→finalizing→completed`；`created|payment_pending→canceled`；`payment_confirmed|finalizing→recovery_required`；`recovery_required→manual_review`。禁止 `payment_confirmed→payment_pending`（INV-02/03）。非法迁移抛业务错误。状态迁移写审计事件（复用既有事件/审计机制）。`snapshot!` 冻结一次后不可覆写。

**不实现**：Start/Resume（TXN-P2-2）、PaymentFactResolver（TXN-P2-3）、Recovery（TXN-P2-4）、Unified Finalize（TXN-P2-5）、API/前端（TXN-P2-2/6）——本包严格 Scope Lock（P2 源 §51、TXN-P2-0 §6.14）。

## 影响范围

纯增量：`pallastrade_core` models 新增 2 文件、backend 新 migration 1 个、specs 新增 3-4 个；无既有文件行为变更。不改 Order/Payment/PaymentSession/PaymentCombination。

## 技术方案（初步）

按 customization 决策树：framework-core 数据层 → 直接新增 core 模型（对齐 `PaymentCombination` 结构：`has_prefix_id :txn`、`SingleStoreResource`、`self.event_prefix`、`publishes_lifecycle_events`、state_machine + 业务错误类），migration 置于 `backend/db/migrate/`（新文件），`TransactionOrder` 关联 + 索引。**删除审计 DB 提案中的 `lock_version` 列**（data-model 教训）。`snapshot!` 作为模型方法（事务内写）+ 校验不可覆写。

## 风险点

- 最高风险：状态机与既有 `state_machines` 在 Order 上的占用/谓词覆盖教训（P0/P1）——CommerceTransaction 为独立新模型无此冲突；但遵循 PaymentCombination 已验证模式。
- 回滚：纯新增表/模型/测试，无数据迁移与行为变更 → 低风险（`rake db:rollback` + 删除文件即可）。
