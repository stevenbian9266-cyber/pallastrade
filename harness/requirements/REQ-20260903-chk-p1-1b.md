## 任务类型

功能优化（CHK-P1-1B：Order Checkout Mutation Facade —— 只 WRAP 既有 Domain Services）

## 需求描述

在 `PallasTrade::OrderCheckout` 命名空间新增三个 mutation 编排服务（只 WRAP 既有服务并返回最新 CheckoutView，禁止复制已有 mutation/重算逻辑）：

1. `OrderCheckout::UpdateContact` —— WRAP `Orders::UpdateContactInformation`（email）→ CheckoutView。
2. `OrderCheckout::UpdateAddress` —— WRAP `Orders::UpdateShippingAddress`（shipping_address 赋值 + sync_shipments；`!completed?` 限定；不重置状态机）→ CheckoutView。
3. `OrderCheckout::SelectShipping` —— WRAP `Shipments::Update`（order 首个未取消 shipment 上选 `selected_shipping_rate_id`，rate 必须属于该 shipment 的可用 rates；`!completed?` 限定）→ CheckoutView。金额/状态重算完全由 `Shipments::Update` 既有语义负责（不新增 tax/price-version 逻辑，P1-2 负责 invalidation 一致性）。

API：`PATCH /api/v3/store/orders/:order_id/checkout`（body 支持 `{ contact: { email } }` / `{ shipping_address: {...} | shipping_address_id }` / `{ delivery_rate_id }` 之一）→ 执行对应 mutation → 返回最新 CheckoutView（200）。访问控制复用 OrderResolvable（:update ability）；404/403 既有语义。

范围锁：不改 Payment 链 / DB / Storefront / SDK；SelectShipping 不含 tax requote（沿用 Shipments::Update 现状，P1-2 记录）；billing 独立编辑 DEFERRED；ApplyPromotion DEFERRED（仅 Cart 域）。

## 技术方案（初步）

1. 三服务均 `prepend ServiceModule::Base`，`call(order:, **)`；`!order.completed?` 守卫（completed → failure）；WRAP 既有服务后 `OrderCheckout::View.call(order:)` 返回最新投影；为 P1-2 invalidation 预留注释扩展点（不实现失效图）。
2. SelectShipping：`order.shipments` 取首个可改 shipment（非 cancelled）→ `rate = ShippingRate.find_by_prefix_id!(id)`（或 id）→ 校验 `shipment.shipping_rates.ids.include?(rate.id)` → `Shipments::Update.call(shipment:, shipment_attributes: { selected_shipping_rate_id: rate.id })`；失败透传。
3. Controller `update`：OrderResolvable `find_order!`（:update ability）→ 按 body 键分派单一 mutation → render CheckoutView。一次 PATCH 仅一类字段（防组合歧义）。

## 风险点

- SelectShipping 改选运费会改 amount_due → 与既有 PaymentSession 关系：未完成订单支付前才可改（!completed? 且无成功支付）；若已有 active payment session 金额变化 → 复用/新会话由 P0 Start 幂等处理（amount 变化不 reuse），本包不触碰 PaymentSession。
- Shipments::Update 现语义不重算 tax；运费敏感税在 P1-2 invalidation 处理（记录）。
- legacy checkout 态订单不允许（order API 不暴露 + find_order! scope 排除）。
