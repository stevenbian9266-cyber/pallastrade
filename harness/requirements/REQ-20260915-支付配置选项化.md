优化：管理后台支付配置选项化 —— 切片 1（core Option 模型 + `optionized` 门控）

## 任务类型

功能优化（框架模型扩展，additive）

## 本次交付物

1. `PallasTrade::PaymentMethod` 新增 Option 读取 API：
   - `options`（`metadata["options"]` 归一为数组）
   - `available_options`（`active != false`，按 `position` 排序）
   - `option_for(kind)` / `default_option`
   - `optionized?`（读取 `metadata["optionized"]`）
   - `effective_options`：`optionized?` → `available_options`（可能为空）；未选项化 → 有 options 用之，无 options 回落单条默认入口
   - `frontend_visible?`：`optionized?` 且无可用 options → false（供前台过滤）
2. `Order#collect_frontend_payment_methods` / `collect_backend_payment_methods`：加入 `frontend_visible?` 过滤（未选项化的 provider 行为不变）。
3. 新增 RSpec：`backend/spec/models/pallastrade/payment_method_options_spec.rb`（覆盖默认回落、启停、排序、`option_for`、门控 0 入口）。

## 关键决策（与交付单的偏差）

1. **表单参数前缀 = `payment_options`**（交付单曾写 `payment_method[options][...]`）：与统一命名约定一致，避让 `Gateway#options`。
2. **`optionized` 翻转规则**：`勾选任一入口 || 已选项化` 才置 true；全部取消且原本未选项化 → 保持缺失（前台回落默认入口，防「改名保存即清空前台」回归）。已选项化后全部取消 → 0 前台入口（FR-007 语义）。
3. **目录外 kind 忽略**（防注入）；**未随表单提交的既有 kind 原样保留**（API/历史数据不因保存丢失）。
4. **落库用 `update_columns(private_metadata:)`**：`metadata` 只是 `private_metadata` 的 API 别名（`update_columns` 不认别名）；且绕过 provider 校验（Stripe `validate_secret_key` 会发远端请求）。
5. **TestConnection 置于 core**（交付单原写 `PallasTrade::Admin::…`）：服务保持纯只读、可重放；落库与审计归 admin 控制器（`PallasTrade::Audit.record(action: 'payment_method_test_connection')`）。
6. **规格适配**：host 不匹配导致的 `OpenRedirectError` 用 `allow_any_instance_of(...).to receive(:location_after_save)` 规避（沿用 `roles_permissions_spec` 既有做法）；store 工厂 code 随机化（规避历史测试库 `pallastrade_1` 残留冲突，已在该 spec 注明）。
7. **SDK dist 不重建**：类型为 additive（前台未消费）；契约同步以 `src/types/generated` + OpenAPI 为准（`generated:check` 的 `contracts.sh` 在 Windows/WSL 下会 SKIP，需 Git bash 手跑）。
