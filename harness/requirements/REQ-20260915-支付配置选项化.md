## 需求标题

优化：管理后台支付配置选项化 —— 切片 1（core Option 模型 + `optionized` 门控）

## 任务类型

功能优化（框架模型扩展，additive）

## 本次交付物

1. `PallasTrade::PaymentMethod` 新增 Option 读取 API：
   - `options`（`metadata["options"]` 归一为数组）
   - `available_options`（`active != false`，按 `position` 排序）
   - `option_for(kind)` / `default_option`
   - `optionized?`（读取 `metadata["optionized"]`）
   - `effective_options`：`optionized?` → `available_options`（可能为空）；未选项化 → 有 options 用之，无 options 回落单条默认入口
   - `frontend_visible?`：`optionized?` 且无可用 options → false（供前台过滤）
2. `Order#collect_frontend_payment_methods` / `collect_backend_payment_methods`：加入 `frontend_visible?` 过滤（未选项化的 provider 行为不变）。
3. 新增 RSpec：`backend/spec/models/pallastrade/payment_method_options_spec.rb`（覆盖默认回落、启停、排序、`option_for`、门控 0 入口）。

## 切片 2 交付物

1. `PallasTrade::Api::V3::PaymentMethodSerializer`（store）additive 新增：`kind`（默认入口 kind）、`frontend_kind`（`inline` / `manual`）。
2. `PallasTrade::Api::V3::Store::Checkout::CheckoutSerializer#payment_method_payload` 同步补 `kind` / `frontend_kind`（两处契约保持一致）。
3. `PallasTrade::Api::V3::Admin::PaymentMethodSerializer` additive 新增 `options`（该 provider 的 method 目录：`kind` / `name` / `frontend_kind` / `active` / `position`）。
4. `PallasTrade::PaymentSessions::Start`：
   - `payment_method_available?` 增加 `frontend_visible?`（optionized 零入口 → 拒绝）；
   - 新增可选参数 `option_kind:`：提供时校验该 provider 下该 kind 存在且 `active != false`，否则拒绝；不提供 → 行为与现状完全一致（零回归）。
5. `orders/payment_sessions_controller` 透传 `option_kind`（可选）。
6. RSpec：`payment_sessions/start_spec.rb`（option_kind 通过/停用/未知 kind/frontend_visible? 四类）、serializer 断言（store `kind`/`frontend_kind`、admin `options`）。
7. PRD changelog 0.3 + 索引状态同步（含切片 1 已交付记录）。
