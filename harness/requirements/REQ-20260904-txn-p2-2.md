## 需求标题

TXN-P2-2：以 `Transactions::Start` 作为 durable 交易启动入口（幂等 + 报价同意 + `PaymentSessions::Start` 委托 + session 关联），并暴露单订单 Store API（start/resume）。

## 任务类型

新功能

## 需求描述（业务语言）

用户确认下单后，系统应记录"这笔交易"（冻结当时的报价、挂上参与订单），并据此发起/复用支付会话；重复点击或超时重试不会产生第二笔交易或重复收款；若报价过期且价格/内容变了，先请用户确认新报价再支付；支付后可从交易视图查看状态。

## 影响范围

core 服务 2 个 + core model 关联（PaymentSession↔CommerceTransaction 可空）+ migration（session.transaction_id）+ api store 端点 2 个 + serializer + store.yaml 增量 + specs。不改既有 `payment_sessions` 端点行为；storefront 不变（TXN-P2-6）。

## 技术方案（初步）

`Transactions::Start`：Resolve participants → CheckoutSnapshot → Readiness →（过期 Refresh）→ quote consent 比对 → 幂等查找 active transaction（`active_for_order`）→ 新建时 `snapshot!` + `TransactionOrder.create!(role)` → `PaymentSessions::Start.call(order:, payment_method:, external_data:, expected_version:, expected_price_version:)`（保留 gate 双层防御）→ session.update(transaction_id)。锁/事务边界沿用 P0（provider I/O 在锁外）。Resume = 只读聚合。API：`POST /orders/:order_id/transactions`（OrderResolvable+ownership）、`GET /transactions/:id`。

## 风险点

- 幂等键/active 判定错误 → 双交易；用 order+purpose+active 状态 + 行锁 + 唯一约束兜底（TXN-P2-1 已有 active_for_order + unique [txn,order]）。
- quote consent 误判（Refresh 自增 version）→ identity 不含版本；用商业事实比对（金额/行项目/运费/promo/tax）。
- API 面扩大 → 本包仅单订单端点；组合/补付/前端延后。

## 决策节点

⏸️ 请确认：① 范围=core 服务+migration+单订单 API（组合 Start/前端延后）；② 409 用 `QUOTE_CHANGED` 错误码（区别于 P1-5 `checkout_version_conflict`）；③ 复用 `PaymentSessions::Start`（不重写）；④ 旧 payment_sessions 入口保持兼容。
