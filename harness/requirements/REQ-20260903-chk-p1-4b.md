## 需求描述

把后端 PATCH checkout（mutation facade）与 409 quote-conflict 接到 storefront：

1. **SDK**：`orders.checkout.update(orderId, params)`（body：contact / shipping_address / shipping_address_id / delivery_rate_id 其一）→ `Promise<CheckoutView>`。
2. **读取层**：`lib/data/order-checkout.ts` 增 `updateOrderCheckout(orderId, params)`（server action）：成功返回 {view}；409/业务错误返回结构化 {error}（供 UI 提示）。
3. **OrderPaymentContent 编辑 UI（or_ 页）**：
   - 收货地址区加「编辑」：复用 AddressFormFields + 保存 → updateOrderCheckout({shipping_address}) → 刷新 view；
   - 物流区（若有 fulfillments.shipping_rates）加 rate 单选：保存 → updateOrderCheckout({delivery_rate_id}) → 刷新 view；
   - 刷新后金额/version 以新 view 为准（ready 门控/409 逻辑不变）。
4. **409 UI**：createOrderPaymentSession 返回 `checkout_version_conflict` → toast 提示「订单内容/金额已更新，请确认」+ 重新 `getOrderCheckout` 刷新 view（不自动重试支付）。
5. **PRD §12 CHK-P1-1B**：`OrderCheckout::ApplyPromotion` 标注 DEFERRED（Order 域无既有 WRAP 服务；仅 Cart 域），消除文档-实施不一致。

范围锁：不改后端端点（已就绪）；不改 UnifiedCheckout/PaymentCheckoutModal/组合支付；不做 legacy 分支（4C）；不做 address 之外字段（billing DEFERRED）。

## 技术方案（初步）

1. SDK：`CheckoutUpdateParams` = `{ contact?: {email}, shipping_address?: AddressParams, shipping_address_id?: string, delivery_rate_id?: string }`；`update` PATCH `/orders/${id}/checkout`。
2. OrderPaymentContent 状态：`view`（props，可被刷新 state 替换）、`editing`（'address'|'delivery'|null）、`saving`、`conflictMsg`。保存/409 后调 `getOrderCheckout(order.id)` 更新本地 view（server action 无法改 props → 将 view 存入组件 state 并同步 summary/地址/物流）。
3. 409 处理：order-payment.ts createOrderPaymentSession 返回错误透传（现有 actionResult error）；调用方检查 error 含 code checkout_version_conflict → toast + 重取 view。
4. i18n：`editAddress`/`editDelivery`/`save`/`cancel`/`quoteUpdated`/`saved` 等 key（5 locale）。

## 风险点

- 编辑后金额/税/物流变化 → view 刷新以服务端返回为准；PATCH 返回最新 view 直接采用（免二次 GET），仍失败则 GET。
- 编辑仅 !completed（后端守卫）；账户补付 completed 订单进入本页时无编辑入口（保持只读）。
- 409 只在会话创建时返回（Start 比对）——UI 不自动支付，避免金额不确定下重复扣款。
