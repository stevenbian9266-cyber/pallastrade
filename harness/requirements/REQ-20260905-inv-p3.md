## 目标

在不重写库存引擎的前提下，将 `StockReservation` 纳入 `CommerceTransaction` 生命周期，建立
`Reserve → RESERVED → canonical Finalization/StockMovement(physical consume) → COMMITTED` 正常链 +
`RESERVED → RELEASED / EXPIRED` 未消费终态，并使 PAID+库存异常进入 P2 Recovery。

**关键架构约束（PRD v0.2 冻结）**：
- `StockItem.count_on_hand + StockMovement` = 唯一 physical inventory authority；Reservation 只做 soft allocation，**不修改 count_on_hand**。
- **COMMITTED = canonical physical consumption 成功后的 Reservation 事实确认，P3 不建立第二套 physical decrement**。
- 不建第二张 Reservation 表；不引入 DB 2PC / 强制 MQ；不重写 Quantifier/Coordinator/StockItem/StockMovement。

## 需求描述

分 8 个实施包（INV-P3-0..7），详见 PRD §3 FR-001..056：

1. **INV-P3-0 Inventory Semantic Freeze（只读，先执行，完成后停止评审）**：输出 20 项审计产物（含 PHYSICAL_CONSUMPTION_MATRIX、COMMIT_SEMANTICS）+ 冻结 7 策略（INVENTORY_AUTHORITY/RESERVATION_IDENTITY/RESERVATION_LIFECYCLE/RESERVATION_TIMING/RESERVATION_TTL_POLICY/INVENTORY_RECOVERY_POLICY/COMMIT_SEMANTICS）。**未批准前禁 migration/禁 schema 修改/禁接入 Start/Finalize/Recover（FR-005/AC-3026）**。
2. INV-P3-1 Lifecycle Foundation：StockReservation 状态化（RESERVED/COMMITTED/RELEASED/EXPIRED）+ timestamps + release_reason + `commerce_transaction_id` 可空 FK + state-aware 唯一约束 + 安全 backfill；Release/Expire 改状态流转；Quantifier 只统计 active RESERVED。
3. INV-P3-2 Snapshot V2 + Reserve 接入：Snapshot schema_version=2 + inventory demand evidence；`Transactions::Start` Reserve before PaymentSession（幂等/悲观锁/组合 business-level all-or-nothing）。
4. INV-P3-3 Canonical Finalization/Commit：`Transactions::Finalize` 保留现有 physical decrement，成功后 Reservation→COMMITTED（InventoryCommitCoordinator，幂等）；`Carts::Complete` transaction-aware path 不硬删除；PAID+Finalize 失败→recovery_required。
5. INV-P3-4 Release/Expiration/TTL：Release 门控（PaymentFact）、cancel 接线、ExpireJob 状态化+调度、TTL/3DS 不变量。
6. INV-P3-5 InventoryFactResolver + Recovery：Recover 扩展 Payment→Inventory→决策矩阵。
7. INV-P3-6 Combination/Legacy Convergence + Storefront 错误码。
8. INV-P3-7 Operational Hardening：Admin inventory 面板 + inventory.* 审计 + trace + metrics hook。
