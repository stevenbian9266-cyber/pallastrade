## 任务类型

功能优化（CHK-P1-3：Server Readiness / CheckoutSnapshot / Payment Start Gate / PaymentSession 记录 price_version）

## 需求描述

在 OrderCheckout 层与 PaymentSessions::Start 建立「报价（quote）生命周期」护栏，并暴露只读 Readiness/Snapshot：

1. **OrderCheckout::Readiness**（只读服务）：聚合既有 Order/Shipment 谓词（email/ship_address/amount_due/shipment selected rate），返回 `ready` + `missing_requirements`（code 数组：`contact`/`shipping_address`/`delivery_rate`/`balance`）。不复制校验规则；legacy/完成态订单不误报（digital 免 shipping_address；无 shipments 免 delivery_rate）。
2. **OrderCheckout::Snapshot**（只读服务）：确定性 transaction projection 值对象——`order_id/prefixed + number/state/currency/checkout_version/price_version/checkout_expires_at + 权威金额列 to_s` + `fingerprint`（SHA256 前 16 hex）。零副作用；不落库（PRD 禁 CheckoutSession/新表）。
3. **Payment Start Gate（quote 作用域，作用于标准流 pending/paid 未完成订单且有 checkout_expires_at）**：
   - **过期自动 Refresh**：`Expiration.expired?` → `OrderCheckout::Refresh`（Recalculate + 续期）→ 继续以新权威金额支付；标记 `quote_refreshed: true` 入 session external_data（客户端可感知）。
   - **就绪拦截**：Readiness 缺 `contact`/`shipping_address`/`delivery_rate` → `failure({code:'checkout_not_ready', missing_requirements:[...]})`（不建会话）。
   - **无 quote 订单直通**（`checkout_expires_at` nil）：行为与现状完全一致（start_spec/legacy/直付回归不破坏）。
4. **PaymentSession 记录 price_version**：新会话 external_data merge `price_version`（来自锁内 reload 的权威 order）+ 过期刷新时 `quote_refreshed: true`。无 migration。
5. **CheckoutView/Serializer 输出 `ready` + `missing_requirements`**（只读，供 P1-4 storefront 消费）。

范围锁：不改 legacy cart/checkout 行为；不做 409 CHECKOUT_VERSION_CONFLICT（后续包）；不改 OrderUpdater/定价公式/状态机；不加表；不改 Storefront/SDK；PaymentSessions::Start 的幂等/reuse/operation_key/reconcile 契约不变。

## 技术方案（初步）

1. Readiness：
   - requirements 判定（全委托既有谓词）：`contact`=email.present?；`shipping_address`=`!requires_ship_address? || ship_address.present?`；`delivery_rate`=`shipments.empty? || shipments.any? { selected_shipping_rate.present? }`；`balance`=`amount_due.to_d.positive?`。
   - `ready` = 无 missing。
2. Snapshot：DTO 只读冻结；`fingerprint = SHA256([order_id,checkout_version,price_version,currency,amount_due].join('|'))[0,16]`（与 Recalculate 指纹基座一致精神，含版本，供后续 409 比对）。
3. Start gate（置于 `call` 顶部、首个 with_lock 前，Refresh 自带锁，避免嵌套）：
   ```
   quote_active = order.standard_flow? && !order.completed? && order.checkout_expires_at.present?
   if quote_active && Expiration.expired?(order:) → Refresh → success? ? order=view.order, quote_refreshed=true : return failure
   if quote_active && !Readiness.ready?(order:)（仅 contact/shipping_address/delivery_rate 阻塞，balance 由既有 amount 检查负责）
       → failure(order, { code:'checkout_not_ready', missing_requirements: [...] })
   锁内捕获 price_version → create_payment_session external_data merge { price_version:, quote_refreshed? }
   ```
4. 幂等保护：gate 不改变 operation_key 计算（amount 变化自会新 key）；复用比对仍只看 mode/amount/窗口。

## 风险点

- 在标准流「有 quote 但缺就绪字段」时开始支付被拒——新行为；但真实 submit 订单已含地址/email/物流快照，仅 PATCH 移除才可能触发（1B mutation 均有 !completed? 守卫与 recalc），属护栏预期。
- `start_spec` 等既有最小 pending order（无 expires_at/无地址）→ quote_active=false 直通，P0/回归不受影响。
- completed（账户补付）订单 quote_active=false（!completed? 守卫）→ 直通，order_payment_sessions_controller_spec 不受影响。
- Refresh 在 gate 内失败（如 completed 竞态）→ 透传 Refresh failure（不建会话）。
