## 任务类型

功能优化（CHK-P1-2：Checkout Version / Price Version / Expiration / Recalculate / Refresh；不含支付闸门）

## 需求描述

在 Order 上引入受控版本/过期能力并接入 OrderCheckout 层：

1. **Migration**：`orders` 加 `lock_version`（integer default 0；AR 乐观锁，防并发 mutation 覆盖）、`price_version`（string 可空；影响金额输入确定性指纹，PRD 禁 public_metadata/updated_at 冒充）、`checkout_expires_at`（datetime 可空；报价过期时间，非取消/abandoned）。
2. **OrderCheckout::Recalculate**：WRAP `OrderUpdater.new(order).update`（幂等 recalc：tax/promo/shipment adjusters → totals）；随后按订单金额权威列集合计算并落 `price_version`（SHA256 摘要前 16 hex）；若 `checkout_expires_at` 为 nil 则初始化为 now+window（window=Config[:checkout_quote_window_minutes]||30）。返回 reload 后 order。
3. **OrderCheckout::Refresh**：`!completed?` 守卫；Recalculate + `checkout_expires_at = now + window`（续期）；返回最新 CheckoutView。
4. **Mutation 接入**：UpdateAddress/SelectShipping 成功后经 Recalculate（补 tax/price_version；SelectShipping 的 Shipments::Update 重算仍先执行，Recalculate 幂等补齐）；UpdateContact 不 recalc（金额无关，lock_version 随 save 自然递增）。并发 stale 写入由 AR 乐观锁抛 `ActiveRecord::StaleObjectError`。
5. **API**：CheckoutView/Serializer 输出正式 `version`(=lock_version)、`price_version`、`expires_at`(=checkout_expires_at iso8601)；controller `update` rescue `StaleObjectError` → 409（`CHECKOUT_VERSION_CONFLICT`）。
6. **Expiration 判定服务**（只读，供 P1-3 gate）：`OrderCheckout::Expiration`——`expired?`/`expires_in`/`valid?`（供后续支付闸门复用；本包不接入 PaymentSessions::Start）。

范围锁：不改 Payment 链（Start gate P1-3）；不改 Storefront/SDK；无 CheckoutSession/新表；价格公式仍由既有 updater 权威（Recalculate 只编排不复制公式）。

## 技术方案（初步）

1. price_version 指纹：`Digest::SHA256.hexdigest([currency, item_total, shipment_total, adjustment_total, included_tax_total, additional_tax_total, promo_total, total, amount_due].map(&:to_s).join('|'))[0,16]`——在 OrderUpdater 落库后读取权威列生成。
2. CheckoutView 委托 `lock_version`（→serializer `version` 数值）、`price_version`、`checkout_expires_at`（→`expires_at` iso8601）。
3. controller update rescue：`rescue_from ActiveRecord::StaleObjectError` → render 409 conflict（code CHECKOUT_VERSION_CONFLICT）。

## 风险点

- 引入 lock_version 乐观锁可能使既有直接 `order.update!` 路径在并发时抛 StaleObjectError（框架侧调用点）——受控：仅 OrderCheckout mutation 路径强依赖；AR 乐观锁在 update 冲突时抛错为预期（409）；既有非 checkout 更新同一订单并发本就应失败（防覆盖），影响待回归观察。
- OrderUpdater.update 全量跑的成本（读多行订单 recalc）可接受；Refresh 显式调用。
- migration 在 dev/test 应用；生产按 Runbook。
