## 任务类型

新功能（core 只读 transaction 级聚合 + 核对服务 + 2 个 transient VO；**无 migration/API/UI**）

## 需求描述

实现 CommerceTransaction 级 Transaction Financial Reconciliation（P4 §63/§36 第二层/§38）：`Reconciliations::ReconcileTransaction.call(transaction:)` 只读编排——local 面从 immutable Journal（`FinancialLedgerEntry.active.by_transaction`）按 entry_type 聚合（CASH_CAPTURED→cash_captured / STORE_CREDIT_APPLIED→store_credit_applied / OFFLINE_PAYMENT_RECORDED→offline_payment_recorded / REFUND_SUCCEEDED→refund_total / ORDER_ALLOCATION→allocation_total）；provider 面复用 FIN-P4-6 逐 payment/refund SourceResult 聚合（provider gross/fee/net）；§38 核对矩阵（allocation vs captured → ALLOCATION_MISMATCH；refund vs captured → REFUND_MISMATCH；provider gross vs local → AMOUNT_MISMATCH；commercial vs captured：short-paid 合法不 alarm、over → COMMERCIAL_AMOUNT_MISMATCH）；状态合成（journal 缺失→NEEDS_ATTENTION+JOURNAL_POSTING_MISSING；settlement pending→PENDING 不误报；legacy→UNSUPPORTED 非 MISMATCH；无 PSP→provider 面 NOT_APPLICABLE）。输出 `TransactionResult` + `TransactionFinancialSummary` transient VO（§25 字段 + short_paid?/overpaid? 派生 helper；freeze）。只读/幂等/零副作用（§44/§46/AC-4023/INV-09）；绝不自动 charge/refund/倒退 transaction（INV-11）。结果不落表（§25 首版不必落表 → P4-8）。无 migration/API。

## 影响范围

- 变更：core 新增 `reconciliations/{transaction_result,transaction_financial_summary,reconcile_transaction}.rb`；specs（backend）+ skills/scenarios/PRD。
- 不改：Payment/Refund/Transaction state machine、Journal/Post/Reverse、P4-6 reconcile 服务、fetch_* 契约路径；无 migration/schema；无 API/storefront/platform。

## 技术方案（初步）

见 PRD §7。关键：local 金额唯一权威 = immutable Journal（不从 Payment 现算 cash）；provider 面复用 P4-6（不重复实现 provider fetch）；构造端一律字符串常量（P4-6 symbol 坑）；Journal 缺失暴露 NEEDS_ATTENTION 不猜（INV-09/12）；纯函数幂等（AC-4024）。

## 风险点

- 最高风险：reconcile 意外副作用（改 Payment/Journal/Transaction/自动资金动作）→ 只读 spec 强证（AC-4023）。
- 中风险：Journal 缺失误当 0 或误 alarm → JOURNAL_POSTING_MISSING 暴露 + short-paid 合法不 alarm。
- 中风险：组合/多支付聚合口径错误（双计/漏计）→ 以 Journal by_transaction 单源聚合 + 组合 fixture 集成。
- 回滚难度：低（新增 VO/服务，无 schema/既有行为变更）。
