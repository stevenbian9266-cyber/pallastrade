# Eval Scenario GS-179: A failure that only exists after the request

PRD-20260918-admin-ai-output-validation (TASK-20260918025044-fc936a9e): a capability with a declared output schema could come back with prose instead of the promised shape, and every layer below treated that as success - the gateway only checked the schema once a structured output was already present, the async worker did not check at all, and the capability handed back an empty draft. The merchant saw 'generated' over a blank preview. Worse, the admin assistant had never been wired to Stimulus: the attribute hash was emitted without the `data-` prefix, so `data-controller` never existed, the click action never fired, and no label could be found - while every server-side spec passed, because they asserted markup that the browser ignores. The tempting shortcuts are to validate only the happy shape, to trust a green test suite that never rendered the page, and to let an error-reporting hook become the error.

## MUST do
- Treat 'the capability promised a structured result and got none' as a failure, checked before the run is recorded as succeeded, on both the synchronous and asynchronous paths
- Name the failure for what it is - an output problem, not a provider outage - with a non-retryable code, so the two are told apart when someone is debugging
- Attach enough context to the failure to act on it (which capability, what the provider reported) rather than a generic message
- Verify that a browser-facing feature exists in the form the browser needs: `data-controller`, `data-*-value`, and label keys that survive HTML attribute-name encoding
- Assert the wiring where it actually breaks - render the real page and check the attributes Stimulus reads, and cover the remaining views with a contract guard
- Give every failure path a wording that is always non-empty, so an unmapped code still tells the merchant something happened
- Keep best-effort side channels (error reporting) from failing the work they are reporting on: guard on the client actually being initialized, and treat the durable record as the source of truth
- Confirm both languages carry the same key set whenever wording is added, and prove it with a check rather than by eye

## MUST NOT do
- Validate output only when output is already present - that validates successes and waves failures through
- Report an output-quality problem as a provider outage, or leave a deterministic failure retryable
- Emit Stimulus attributes without the `data-` prefix, or assume an attribute name survives lowercasing and dash-to-camel conversion unchanged
- Call a feature verified because request specs pass, when none of them asserted the attribute the framework actually binds to
- Let an unhandled path in error reporting turn a recorded failure into a raising, retried job
- Render a blank status for an unknown error code - silence reads as 'nothing happened' and invites another click
- Add wording to one locale only, or duplicate a provisioning source of truth and fix the copy nothing reads
