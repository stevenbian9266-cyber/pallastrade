# Eval Scenario GS-028: SEO 301 redirects: resolve + middleware degrade-open

PallasTrade::Redirect maps per-store from_path → to_path (normalized: leading slash, strip trailing slash; from_path strips pasted origin; to_path must be internal). Redirects carry optional business-facing title/description (columns added 2026-08-15) so the admin list is readable (Title column first, position 5); Admin API permitted_params and admin redirect_serializer both expose title/description. Store API resolve returns {path, status_code} or null; storefront middleware issues NextResponse.redirect guarded against A→A loops and degrades OPEN on API failure (Turnstile-style). Admin API /api/v3/admin/redirects is full CRUD behind read/write_settings. Admin pages must carry plain-language explainer copy (page_alerts intro on index, form_intro on new/edit via shared _form) so non-technical users understand the feature (old link → new link, prevent 404, keep SEO rank). The redirects index also shows a 'Products with changed URLs' list (from friendly_id `friendly_id_slugs` history via PallasTrade::ProductUrlChange — old slug ≠ current, excludes deleted- slugs and already-handled from_paths) with one-click links that pre-fill /admin/redirects/new?from_path=/products/{old}&to_path=/products/{new} (RedirectsController#new reads those query params). Next.js 16: the 301 resolution lives in src/lib/pallastrade/middleware.ts (createPallasTradeMiddleware) wired via src/proxy.ts — do NOT add a separate src/middleware.ts (Next 16 rejects middleware + proxy coexistence). Storefront must pass pnpm check (Biome) before commit — new image/srcset paths use plain <img> with CDN webp variants, not the Next.js optimizer.

## MUST do
- Normalize paths on save (leading slash, no trailing slash; from_path origin-strip; to_path internal-only)
- Enforce unique from_path per store; active scope ignored in resolve
- Resolve endpoint returns target + status on hit, data:null on miss
- Storefront middleware 301s on hit with loop guard and 60s revalidate cache
- Degrade open (continue rendering) when the resolve API is unreachable
- List products whose URL changed (friendly_id_slugs history via PallasTrade::ProductUrlChange) on /admin/redirects with one-click redirect creation (prefilled from_path/to_path)

## MUST NOT do
- Allow external URLs as to_path (open-redirect)
- Redirect A → A (loop)
- Fail the storefront when the redirect service is down
- Run CDN webp variants through the Next.js optimizer again (double encoding)
