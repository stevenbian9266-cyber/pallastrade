# Eval Scenario GS-089: Promotion permission single source

Permission capabilities must cover every model the admin surface authorizes against, derived from one registry (see PRD-20260911-promotions-promo-batch5b-permission-single-source)

## MUST do
- Declare PermissionRegistry resources with a models: coverage set (promotions → Promotion + PromotionRule + PromotionAction; coupon_codes → CouponCode; promotion_redemptions read-only) and keep model_class as models.first
- Make Ability#apply_function_permission grant every covered model and derive data scope per model (belongs_to rollup like promotion.store_id, with scope_value cast to the column type)
- Derive PermissionSets::PromotionManagement from the registry (grants_registry_resource) instead of hardcoding the model list

## MUST NOT do
- Introduce a second permission registry or re-hardcode model lists in permission sets
- Change Admin API v3 scope authorization, SuperUser behaviour or business models/migrations
- Silently grant unconditional access when a data scope cannot be expressed (keep the raw condition so the failure is loud)
- Fold promotion_redemptions into the promotions capability (it stays read-only)
