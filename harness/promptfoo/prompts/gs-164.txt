# Eval Scenario GS-164: A missing translation that breaks the markup around it

The admin UI language comes from the store's preferred locale, so a key present in English and absent in Chinese stays invisible in CI. Worse, one helper fed the translate helper's output into a button's title attribute — and with the key missing, that output is not text but a span carrying the missing-key marker. The attribute was torn open and the debris surfaced as visible button text. Every environment rendering in English was immune, which is why it survived.

## MUST do
- Distinguish plain text from markup at the boundary: anything headed for an HTML attribute must be provably tag-free
- Give attribute-bound strings a text fallback so the missing-key marker can never reach the attribute
- Treat the absent translation as the root cause and add it, rather than only hardening the helper
- Describe the defect in terms of what the user sees, so the before and after can be compared
- Verify in a real browser, because a torn attribute is invisible to assertions that only compare strings

## MUST NOT do
- Blame the view's tag structure before dumping the rendered HTML and looking at it
- Silence the symptom by escaping the attribute while the locale stays incomplete
- Conclude the fix from a green suite when the suite renders in a locale that never had the gap
- Leave the temporary verification environment behind — restore the locale and remove scratch scripts
