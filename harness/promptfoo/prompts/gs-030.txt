# Eval Scenario GS-030: CMS blog posts: Post model + Store/Admin API + admin UI + storefront /blog + SEO/sitemap + SDK posts

PallasTrade::Post (core model, table pallastrade_posts, store-scoped, TranslatableResource title/excerpt/seo_title/seo_description + ActionText body + FriendlyId slug unique per store + has_one_attached cover_image; published_at nil=draft, future=scheduled) is the single source of truth for blog content. Store API GET /api/v3/store/posts (published only, newest first, {data,meta}) and /posts/:slug (or post_xxx) expose published posts; drafts/scheduled 404. Admin API /api/v3/admin/posts is full CRUD behind read/write_settings, includes drafts/scheduled, serializer exposes status (draft/scheduled/published). Admin UI /admin/posts (Blog sidebar menu, ResourceController + TableConcern, ActionText editor + cover upload + publish datetime). Storefront /blog + /blog/[slug] under (storefront) route group, src/lib/data/posts.ts (listPosts/getPost via sdk posts.list/get), PostCard component, generateMetadata with seo_title/seo_description + JSON-LD Article, posts added to sitemap.ts, blog namespace in all 5 locale files. SDK @pallastrade/sdk exposes client.posts.list(params?, options?) -> PaginatedResponse<Post> and posts.get(id, options?); Post type + PostSchema generated by Typelizer. API docs synced in backend/public/api-docs/{store,admin}.yaml + platform/docs/api-reference/. Skill updates: pallastrade-api-v3 (posts endpoints), pallastrade-data-model (Post model), pallastrade-storefront (blog section), pallastrade-typescript-sdk (posts resource).

## MUST do
- Store-scope Post through current_store / store.posts; never cross-store queries
- Store API returns only published posts (drafts/scheduled 404); Admin API returns all with status
- Reuse TranslatableResource + ActionText + FriendlyId (same infra as Policy), not new ad-hoc i18n
- Provide admin UI with ActionText editor, cover upload and publish state, plus a Blog sidebar entry
- Add storefront /blog + /blog/[slug] with generateMetadata (seo_title/description + JSON-LD Article) and include posts in sitemap.ts
- Add client.posts to @pallastrade/sdk and rebuild dist; export Post type/schema
- Sync backend/public/api-docs/{store,admin}.yaml + platform/docs/api-reference/ and update the 4 affected Skills

## MUST NOT do
- Expose raw integer primary keys in API responses
- Leak draft/scheduled posts through the Store API
- Hand-edit the auto-generated OpenAPI YAML schema section without matching serializer output
- Skip storefront blog page tests or sitemap coverage
- Push while harness doc-impact reports docs-required (scenarios.json must change when Skills change)
