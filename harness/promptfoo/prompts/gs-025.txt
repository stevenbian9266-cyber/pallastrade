# Eval Scenario GS-025: Storefront cookie consent: banner + settings page + third-party gating

When adding cookie consent (GDPR/CCPA) to the storefront, provide a first-visit consent banner (Accept all / Necessary only / Customize), a standalone /cookies settings page, a plain-JS-readable consent cookie (pallastrade_cookie_consent), and gate all third-party scripts (GTM, Vercel Analytics, Speed Insights, Tawk.to, Sentry client) behind the visitor's category choices while never gating necessary cookies (cart/auth/locale). All cookie components/tests must stay Biome-formatted (pnpm check passes in CI)

## MUST do
- Show the banner only on first visit (no consent cookie) and never flash it for returning visitors
- Persist consent in a plain-JS-readable cookie (categories + version + timestamp); the consent cookie itself is necessary
- Provide a standalone cookie settings page reachable from the footer, with necessary always enabled and non-toggleable
- Gate third-party scripts by category (analytics: GTM/Vercel/Sentry; marketing: Tawk.to) and load nothing before consent is known
- Keep client-mounted state local to the component that conditionally renders (never cross streaming boundaries — avoids React hydration mismatches)
- Add unit tests for parse/serialize, context actions, banner render/buttons, settings toggles, and script gating
- Sync all new i18n keys across every supported locale file

## MUST NOT do
- Gate necessary cookies (cart token, auth JWT, locale/country) behind consent
- Load third-party scripts before the visitor decides (SSR/first paint must be script-free)
- Put a provider-level 'mounted' flag that changes the tree across Suspense/streaming segments
- Hardcode the consent cookie name or categories in multiple places (single constants module)
- Store the consent cookie with SameSite=None or without an expiry
