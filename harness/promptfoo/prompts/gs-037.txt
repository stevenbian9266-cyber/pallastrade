# Eval Scenario GS-037: Storefront bugfix after rollback to 2155920: average_rating Number guard + checkout hydration (mounted gate + NEXT_PUBLIC_* build/runtime divergence + Stripe key baking)

After rolling back to 2155920 (no order-split/combined-payment), three regressions resurfaced: (1) the PDP crashed with `TypeError: b?.toFixed is not a function` because ProductReviews rendered `averageRating?.toFixed(1)` while the Store API serializes average_rating as a string (BigDecimal) — fixed by wrapping in Number(). (2) checkout rendered blank / stuck skeleton (React #418 hydration mismatch). Root cause: NEXT_PUBLIC_STORE_NAME=PallasTrade-Dev existed only in the runtime env file while the client bundle was built without it (client inlines NEXT_PUBLIC_* at build time, server reads runtime env) — fixed by baking NEXT_PUBLIC_STORE_NAME/SITE_URL/DEFAULT_LOCALE/DEFAULT_COUNTRY as Docker build args (storefront/Dockerfile + deploy.yml + docker-compose.dev.yml) so server and client render the same strings; the mounted gate (SSR skeleton until client mount) is the fallback. (3) the Stripe PaymentElement rendered an EMPTY container on checkout — the rollback dropped the original b68095f Dockerfile `ARG NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` declaration, so the build arg was silently ignored, the client bundle shipped without the publishable key, stripePromise resolved to null, and Elements rendered nothing (backend still created PaymentIntents 201). Fixed by restoring the ARG/ENV + build-arg in Dockerfile/deploy.yml/compose.
