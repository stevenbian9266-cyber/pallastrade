## 二、可沉淀为通用 harness 能力的规则（按价值排序）

### H1. Gate 分支绑定校验（引擎改进）
- kind: engine
- target: bin/gate-lifecycle.mjs + bin/state-store.mjs
- priority: P0
- **现象**：gate 绑定创建时分支/HEAD；在 `main` 误开 gate（R9 要求 dev 开发）→ 切 dev 后 gate 与分支不匹配，被迫删文件重建。
- **通用规则**：gate 创建时记录目标分支；`gate:status` 检测当前分支 ≠ gate 分支时输出明确警告（"gate 绑定 X 分支，当前 Y"），并提示处理方式。
- **沉淀**：`bin/gate-lifecycle.mjs` + `bin/state-store.mjs`。

### H2. 知识同步门"同一 commit"约束提示（引擎改进）
- kind: engine
- target: bin/doc-impact.mjs
- priority: P0
- **现象**：`harness-doc-impact`（pre-push）检查 HEAD..base diff；知识文档（scenarios.json）与被触发代码（SKILL.md）**不在同一 commit** 时被拦；分开 commit 再 merge，merge commit 不含该变更 → 反复被拦。
- **通用规则**：doc-impact 报错信息明确提示"知识文档变更必须与被触发它的代码变更放在**同一个 commit/PR** 中"。
- **沉淀**：`bin/doc-impact.mjs` 错误文案 + `docs/rules.md`。

### H3. 扫描类 CI 检查的通用反模式（内容规则）
- kind: standard
- target: rules/base-standards.json
- priority: P1
- title: Scan-based CI checks must exclude internal records and avoid whole-word bans on common terms
- category: process
- rule: 扫描类检查应排除内部记录目录（记忆/需求/调研/research）；通用英文词不得用整词禁止，改用品牌短语/上下文匹配；检查器自身代码不得含被禁止词（注释自触发）。
- **现象**：ownership-audit 用 `\bword\b` 整词匹配 `upstream`/`spree`，误伤：① 通用英文技术词（upstream、Cloudflare/Next.js 语境）；② 内部记录/调研文档中的**否定性陈述**（"零 Spree 残留"）。
- **通用规则**（写进通用反模式/CI 最佳实践）：
  1. 扫描类检查应**排除内部记录目录**（记忆/需求/调研/research）；
  2. 通用英文词**不得用整词禁止**，改用品牌短语/上下文匹配；
  3. **检查器自身代码不能含被禁止词**（注释自触发——本次踩过）。
- **沉淀**：`rules/base-anti-patterns.json` 补充项 + `docs/rules.md`。

### H4. 长任务 flock 锁的诊断与超时（运维最佳实践）
- kind: docs
- target: docs/lifecycle.md
- priority: P1
- **现象**：pull-deploy 用 `flock -n 9` 锁，卡在 `docker pull ghcr.io`（10+ 分钟）→ 持有 fd 锁 → cron 一直"已有部署进程在运行"；**删锁文件无效**（flock 是 fd 锁，不是锁文件存在判断）。
- **通用规则**：长任务 flock 应：① 给临界操作加超时（`timeout`/`flock -w`）；② 提供诊断命令（`fuser`/`lslocks` 找持锁者）；③ 文档注明"删锁文件 ≠ 释放 flock"。
- **沉淀**：`docs/lifecycle.md` 或模板化部署脚本最佳实践。

### H5. CLI 非 ASCII 参数传递（引擎改进）
- kind: engine
- target: bin/cli-utils.mjs
- priority: P2
- **现象**：`harness knowledge assess --asset "中文资产名"` 在 Windows PowerShell 下传参乱码（GBK 控制台）。
- **通用规则**：CLI 关键参数支持 `--xxx-file` 从文件读取（UTF-8），或文档注明"Windows 下中文参数用脚本文件方式"。
- **沉淀**：`bin/cli-utils.mjs`（getArg 增加文件读取）或文档。

### H6. 测试环境 DB 残留清理（测试最佳实践）
- kind: docs
- target: docs/
- priority: P2
- **现象**：test DB 残留 store（`code=pallastrade_1` 唯一冲突）导致 spec 随机失败；清理 SQL 用 `%q{code LIKE %qpallastrade_%q}` 时 `%` 被当字面量 → 清理失效。
- **通用规则**：① 测试优先用事务回滚（`use_transactional_fixtures`）或 per-suite 清理；② LIKE 清理 SQL 用参数化 + 显式转义。
- **沉淀**：`docs/` 测试最佳实践。

### H7. 加密存储验证方法（安全最佳实践）
- kind: standard
- target: rules/base-standards.json
- priority: P1
- title: Encrypted-storage verification must read the raw column
- category: security
- rule: 验证加密存储时查原始列（before_type_cast / SQL left(col,n)），不用 ORM 解密 getter 判断明文泄露。
- **现象**：验证 DB 密文用 ORM getter（`item.secret_value`）→ getter 自动解密 → 误判"明文泄露"。正确：查原始列（`before_type_cast`/SQL `left(col,20)`）。
- **通用规则**：验证加密存储时查原始列，不用 ORM 解密 getter 判断明文泄露。
- **沉淀**：`rules/base-standards.json`（安全标准条目）。

### H8. "分组.名称"命名转换（编码标准）
- kind: standard
- target: rules/base-standards.json
- priority: P2
- title: group.name key conversion converts only the first separator
- category: code-quality
- rule: `group.name` 命名转换只转换第一个分隔符（sub('_','.')），保留组内下划线，避免将 OSS_ACCESS_KEY_ID 转成 oss.access.key.id。
- **现象**：`env_key.downcase.tr('_','.')` 把所有下划线变点（`OSS_ACCESS_KEY_ID`→`oss.access.key.id`，错误）；正确：`sub('_','.')` 只转换分组分隔符（→`oss.access_key_id`）。
- **通用规则**：`group.name` 命名转换只转换**第一个**分隔符，保留组内下划线。
- **沉淀**：`rules/base-standards.json`（命名规范条目）。

### H9. Rails lazy routes 诊断法（技术参考）
- **现象**：`rails runner` 里 `Rails.application.routes.routes.size` 不准（lazy load），用 `rails routes` 命令为准。
- **沉淀**：`docs/` 技术 FAQ（框架无关，作为诊断参考）。
