## 1. 背景与目标

- **一句话需求原文**：实施调研路线 P0-3 邮件自动化-弃单恢复。
- **背景**：独立站"加购/进结账但未下单"的访客是最大挽回机会（Klaviyo/Shopify 弃单邮件平均挽回 10-20%）。PallasTrade 已有完整基础设施：购物车=Order（state 机 cart→complete）、事件总线（Event+Subscriber）、邮件（BaseMailer+DB 模板 EmailTemplate+EmailLog）、Sidekiq。
- **目标**：弃单检测 + 定时扫描 + 恢复邮件（含 token 恢复链接）+ Admin 配置/列表。
- **成功指标**：弃单（有邮箱、非空车、超阈值未下单）自动发恢复邮件；恢复链接回购物车可续购；发送幂等可审计。

## 2. 用户故事 / 场景

- 作为**运营**，我希望弃单访客在 X 小时后收到恢复邮件，以便挽回转化。
- 作为**访客**，我加购未下单后收到邮件，点链接回到我的购物车继续结账。
- 场景：
  - 正常流：加购→填地址（留 email）→离开→1h/24h 后收到邮件→点链接→购物车仍在→完成下单。
  - 边界：空购物车不触发；无 email（未到 address 步）不触发；已下单/已取消不触发。
  - 异常：多次扫描不重复发送（幂等）；邮件发送失败记 EmailLog 并可重发。

## 3. 功能需求（FR）

- FR-001：`Order` 增加 `last_activity_at`（购物车写操作 touch：cart 服务 update/upsert/empty 及结账步进）。
- FR-002：弃单扫描 Job（定时，批量 `in_batches`，条件=incomplete + 有 email + 有 line_items + last_activity_at 超阈值 + 未通知过）。
- FR-003：`AbandonedCartNotification` 模型（cart、email、sent_at；`(cart_id, email)` 唯一 → 幂等）。
- FR-004：弃单恢复邮件（新 mailer + 模板 `abandoned_cart.recovery_email`，含商品列表 + 恢复链接 `{storefront_url}/{country}/{locale}/checkout/{cart_id}` + `order.token` 经 `BaseMailer#append_token`）。
- FR-005：Admin 弃单通知页（列表/手动触发/测试发送）+ 阈值配置（小时数、开关）。
- FR-006：邮件场景开关：`EmailNotificationScenariosController::SCENARIOS` + `EmailTemplate::KNOWN_KEYS` 登记 `abandoned_cart.recovery_email`。
- FR-007：定时调度机制引入（sidekiq-cron 或 rake+系统 cron），Job 继承 `PallasTrade::BaseJob`。

## 4. 非功能需求（NFR）

- 幂等：同一弃单绝不重复发送（唯一约束 + mark_sent）。
- 性能：扫描 `in_batches(of: 1_000)`；last_activity_at 加索引。
- 合规：邮件含退订（复用 newsletter 退订机制）；仅对有 email 的购物车发送。
- 可审计：所有发送走 EmailLog。

## 5. 验收标准（AC，与测试一一映射）

- AC-001 ← FR-001：加购/更新购物车后 `last_activity_at` 刷新。
- AC-002 ← FR-002/003：超阈值的有邮箱非空弃单产生通知记录，且再次扫描不重复。
- AC-003 ← FR-002：空购物车/无邮箱/已下单的购物车不触发。
- AC-004 ← FR-004：恢复邮件含正确商品与链接；点击链接可回到购物车（token 校验通过）。
- AC-005 ← FR-005：Admin 可见弃单通知列表并可手动触发/测试发送。
- AC-006 ← FR-006：场景开关默认开；关闭后不再发送。
- AC-007 ← FR-007：定时任务注册并在扫描周期内执行（测试用手动触发验证）。
