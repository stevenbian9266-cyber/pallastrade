## 1. 背景与目标

- **背景**：管理后台导航存在 4 类个性化：① 业务条件隐藏菜单（orders_to_fulfill/translations）；② 面包屑需每模块手写 concern+控制器 crumb；③ 主区/设置区两套布局，设置区面包屑溢出 + 多个 section banner partial 分叉；④ 子项 `if:` 无约束可写任意业务条件。
- **目标**：导航配置成为唯一事实源（SCOT）——新增一级+二级菜单"声明即得"（顶级点击、次级恒显、面包屑、页面头全自动）；业务状态用 badge/空态而非隐藏。
- **成功指标**：orders_to_fulfill/translations 常显；设置区面包屑不溢出；新增模块零导航代码；`nav:validate` 强制 schema。

## 2. 用户故事

- 作为管理员，我希望菜单恒定可见（不因业务状态消失），以便学习成本低、可预期。
- 作为开发者，我希望新增一级+二级菜单只写导航配置，面包屑/页面头/次级菜单自动生效。

## 3. 功能需求（FR）

- FR-001（P1）：设置区 `#settings-header` 高度自适应，面包屑不溢出。
- FR-002（P2）：`orders_to_fulfill` 常显 + badge；`translations` 常显 + 空态引导；渲染层"子项恒显"。
- FR-003（P3）：面包屑由导航配置自动推导（path→item 索引），删除手写 concern/crumb。
- FR-004（P4）：单一布局 + page_title 自动 fallback + 设置区 section/tabs 统一（删 4 个 banner partial）。
- FR-005（P5）：`harness nav:validate` schema 校验器 + 全量迁移 + SKILL/GS 沉淀。

## 4. 非功能需求

- 兼容：手写 breadcrumb/page_title 保留为覆盖钩子，渐进迁移。
- 稳定导航：菜单项仅权限过滤，业务状态不隐藏。
- 可维护：SCOT + 校验器防回归。

## 5. 验收标准（AC）

- AC-001 ← FR-001：设置页面包屑 `top >= 0`（浏览器实测不溢出）。
- AC-002 ← FR-002：`orders_to_fulfill` 在 `count=0` 时仍显示（含 badge）；`translations` 单语言店铺仍显示。
- AC-003 ← FR-003：主区/设置区面包屑自动生成（抽查 5 页），无手写 crumb 仍正确。
- AC-004 ← FR-004：主区/设置区页面头一致；section/tabs 统一渲染。
- AC-005 ← FR-005：`nav:validate` 通过；SKILL.md 导航 Schema 章节；GS 场景通过 eval-ai。
