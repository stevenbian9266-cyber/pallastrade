## 1. 背景与目标

- **一句话需求原文**：实现多店铺管理。
- **背景**：
  1. **数据/权限/API 层多店铺已就绪**：`PallasTrade::Store` 一等模型（`has_prefix_id :store`、`default` 标记、markets/channels），一切资源按店铺归属（orders/products/customers/api_keys/email_templates 等）；`PallasTrade::Current.store` 每请求店铺上下文（回退默认店铺）；所有 admin/API 查询强制 `current_store.xxx` / `for_store`（AP-005 反模式 CI 拦截）；`RoleUser` 把用户→角色→店铺绑定；Store API 用 `pk_` key 识别目标店铺（单域名多店铺）。
  2. **但当前 Rails 后台（实际运行）仅单店铺管理**：`stores_controller` 只有 `edit`/`update`（永远编辑 `current_store`）；**无店铺列表页、无新建、无切换**；侧边栏店铺下拉（`_store_dropdown`）只展示当前店铺名 + 查看店铺/编辑主题，**不是切换器**；admin 路由仅 `GET/PATCH /admin/store`。
  3. `platform/packages/dashboard`（React 版 6.0 后台）已是多店铺架构（`/$storeId` 路由 + `<StoreProvider>`/`useStore()`），但**当前生产运行的是 Rails admin**，需在 Rails admin 上补齐多店铺管理。
- **目标**：
  1. 后台**店铺列表页**：展示全部店铺（名称/代码/域名/默认标记/时间）。
  2. **新建店铺**：表单创建（name/code/url 等必填），创建后初始化默认策略/渠道并**自动授予当前超管访问**，可立即切换操作。
  3. **店铺切换器**：侧边栏店铺下拉改为切换器，列出当前用户**可访问的店铺**（RoleUser 授权），切换后 `current_store` 生效，全部后台页面按新店铺作用域。
  4. **权限**：店铺管理（列表/新建/编辑）= 超管（`can? :manage, PallasTrade::Store`）；切换 = 用户需有该店铺 `RoleUser` 授权。
  5. **兼容**：单店铺部署（1 个店铺）行为不变。
- **成功指标**：
  - 超管 5 分钟内完成：新建一个店铺 → 自动切换 → 在店铺内新增商品/查看订单 → 切回原店铺。
  - 无该店铺授权的用户无法切换/访问该店铺数据（403 或回退）。
  - 现有单店铺行为零回归（admin spec 全绿）。

## 2. 用户故事 / 场景

- 作为**超管**，我希望在后台看到所有店铺列表并新建店铺，以便管理多品牌/多业务线。
- 作为**超管**，我希望从侧边栏切换当前操作的店铺，以便在多个店铺间快速工作且数据互不混淆。
- 作为**店铺运营**（仅授权某店铺），我希望只能看到/切换到我有权限的店铺，以便最小授权。
- 场景列表：
  - 正常流：超管进入「店铺」列表 → 看到全部店铺（含默认标记）→ 新建店铺 → 填 name/code/url → 创建成功 → 自动切换并进入新店铺设置。
  - 正常流：侧边栏店铺下拉列出可访问店铺 → 点选其他店铺 → 当前店铺更新 → 订单/商品列表按新店铺展示。
  - 边界：只有 1 个店铺时 → 切换器只显示当前店铺（或隐藏），行为不变。
  - 边界：用户被移除某店铺授权后 → 切换器不再显示该店铺；已停留在该店铺则回退到首个可访问店铺。
  - 异常：新建店铺缺少必填字段（code 重复/name 空）→ 表单校验报错。
  - 异常：直接改 session/URL 切换无权店铺 → 拒绝并回退（不泄露数据）。

## 3. 功能需求（FR）

### A. 店铺列表与新建
- FR-001：后台新增「店铺」列表页（`admin/stores` index）：Ransack 表格展示全部店铺（name / code / url / default 标记 / created_at），支持搜索排序。
- FR-002：新建店铺（`admin/stores/new` + POST create）：必填 name、code（唯一）、url 等（参考 store 工厂字段）；创建时初始化默认策略（`after_create :create_default_policies` 已具备）并确保默认渠道/市场可解析。
- FR-003：新建成功后**自动授予当前用户该店铺的管理角色**（`RoleUser`，role=admin，resource=store），并**自动切换**到新店铺。
- FR-004：店铺编辑（edit/update）保留不变。

### B. 店铺切换
- FR-005：侧边栏店铺下拉（`_store_dropdown`）改为**店铺切换器**：列出当前用户可访问的店铺（`RoleUser.where(user: current_user, resource_type: 'PallasTrade::Store')`），当前店铺高亮。
- FR-006：切换动作（POST `admin/switch_store`）：校验用户对该店铺有 `RoleUser` 授权 → 写入 session（`store_id`）→ 重定向回当前页；无授权 → 拒绝/回退。
- FR-007：`current_store` 每请求解析：优先 session 选中店铺（含授权校验）→ 否则回退用户首个可访问店铺 / `Store.default`；所有 admin 页面复用该机制（无需改各控制器）。
- FR-008：切换后订单/商品/客户/设置等全部按新店铺作用域生效（复用现有 `current_store.xxx` 机制）。

### C. 权限与兼容
- FR-009：店铺管理（列表/新建/编辑）授权 = `can? :manage, PallasTrade::Store`（admin/SuperUser 具备）；Ability 补充 store 管理权限（DB 权限体系经 PermissionRegistry 或默认 admin set）。
- FR-010：切换授权 = 该店铺 `RoleUser` 存在且角色允许访问（SuperUser 可访问全部店铺）。
- FR-011：单店铺部署行为不变（切换器仅显示当前店铺或隐藏）；多店铺时新店铺无商品/订单为正常空状态。

## 4. 非功能需求（NFR）

- 安全：切换必须校验授权（防越权跨店）；session store_id 不可信，每请求重校验；店铺列表/新建仅超管可见。
- 性能：切换器店铺列表单次查询（RoleUser join）；列表页 Ransack 分页。
- 兼容：现有 `current_store` 查询模式零改动；`PallasTrade::Current.store` fallback 链保留。
- 可维护：店铺切换逻辑收敛到单点（base_controller concern），各控制器不感知。
- 可测试：切换授权 + 作用域 spec；单店铺回归。

## 5. 验收标准（AC，与测试一一映射）

- AC-001 ← FR-001：超管打开「店铺」列表页显示全部店铺（含 default 标记、code、url），支持搜索。
- AC-002 ← FR-002/003：新建店铺（合法 name/code/url）→ 创建成功出现在列表 → 当前用户获得该店铺 admin RoleUser → 自动切换到新店铺（URL/侧边栏更新）。
- AC-003 ← FR-002：code 重复 / name 空 → 校验报错不落库。
- AC-004 ← FR-005/006/007/008：侧边栏切换器列出用户可访问店铺；切换后当前店铺更新，订单/商品列表按新店铺数据展示；无授权店铺不可切换。
- AC-005 ← FR-009/010：非超管看不到店铺列表/新建入口；仅有某店铺授权的用户切换器只显示该店铺。
- AC-006 ← FR-011：单店铺时切换器行为正常（仅显示当前店铺），admin 全量回归零失败。
- AC-007 ← FR-004：店铺编辑（edit/update）回归正常。

## 7. 技术影响

- **Admin 控制器**：
  - `stores_controller.rb`：补 `index` / `new` / `create`（参数白名单参照 store 工厂字段：code/name/url/mail_from_address/customer_support_email/new_order_notifications_email/default_currency/supported_currencies/default_locale 等）。
  - 新增店铺切换：`switch_store` 动作（或独立 controller），POST 提交 `store_id` → 校验 `RoleUser` 授权 → `session[:admin_store_id]` → 重定向。
  - `base_controller.rb`（或新增 concern）：`current_store` 解析 = session 选中店铺（授权校验）→ 用户首个可访问店铺 → `PallasTrade::Current.store`；`helper_method :current_store` 收敛（若当前由 fallback 提供则显式化）。
- **路由**：`resources :stores, only: [:index, :new, :create, :edit, :update]` + `post 'switch_store'`。
- **视图**：
  - 新增 `stores/index.html.erb`（Ransack 表格）+ `stores/new.html.erb`（复用 form/basic）。
  - `sidebar/_store_dropdown.html.erb`：改为切换器（列出用户可访问店铺，当前高亮）。
- **授权**：`Ability` 对 `PallasTrade::Store` 的 manage（admin SuperUser set 已覆盖）；切换授权在 switch 动作内校验 RoleUser。
- **数据**：无迁移（Store 表已存在）；新建店铺走 `PallasTrade::Store.create`（`after_create` 初始化默认策略已具备）。
- **i18n**：`admin.stores.*`（列表/新建/切换）en + zh-CN。
- **Spec**：新增 `spec/requests/pallastrade/admin/stores_multi_spec.rb`（列表/新建/切换/授权/单店铺回归）。
- **无 API 变更**；storefront/platform 不涉及。
- 影响面：`harness affected --base origin/main` 实施时输出。
