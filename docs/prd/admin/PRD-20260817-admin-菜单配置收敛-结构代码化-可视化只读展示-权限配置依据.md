## 1. 背景与目标

- **一句话需求原文**：菜单结构应由技术代码实现，自定义反而增加用户使用成本；菜单结构 UI 可视化保留（直观感受 + 权限配置依据）。
- **背景**：
  1. P4 已上线「菜单配置」可编辑能力（显隐/改名/排序/新增自定义菜单项），P6 又提出"删除菜单/添加二级菜单/URL 引导"三需求。
  2. 深入评估后达成**方向性共识**：菜单是**功能结构**，与路由/权限/landing/active/badge/面包屑强绑定，属于代码表达范畴；开放 UI 结构编辑会带来：①非技术用户需理解 URL/路由（"URL 怎么填"即痛点实证）；②结构与代码分叉产生脏状态（自定义菜单指向已删路由）；③结构变更无法走代码评审/回滚。
  3. 用户决策（2026-08-17 确认）：**完全去掉自定义菜单项**；**菜单配置页全部只读**（仅可视化展示）；可视化树同时作为**权限配置依据**。
- **目标**：
  1. **结构归代码**：菜单树（一级/二级、增删、URL、landing）完全由 `pallastrade_admin_navigation.rb` 等代码定义，UI 不提供结构编辑。
  2. **UI 只读可视化**：「菜单配置」页改为只读导航树展示，让用户直观看到完整菜单结构。
  3. **权限配置依据**：角色「菜单权限」沿用基于同一导航树的**树状勾选**（P2 已实现），可视化树作为其依据。
  4. **移除可编辑能力**：删除 显隐/改名/排序/自定义菜单项 的写入入口与渲染层覆盖合并，避免与代码结构分叉。
- **成功指标**：
  - 菜单配置页无任何编辑控件（只读），用户 0 学习成本理解后台菜单结构。
  - 侧边栏渲染完全由代码导航配置决定（无覆盖层参与），历史 MenuConfig 数据零影响。
  - 角色菜单权限勾选 = 与菜单配置页同一棵树，权限配置准确。

## 2. 用户故事 / 场景

- 作为**超管/运营**，我希望打开「菜单配置」看到当前后台的完整菜单结构（一级/二级），以便直观理解后台导航布局。
- 作为**超管**，我希望在角色编辑页基于同一菜单树勾选菜单权限，以便按角色授权可见菜单。
- 作为**开发者**，我希望菜单结构改动走代码（PR 评审/回滚），以便结构变更可控、可追溯。
- 场景列表：
  - 正常流：超管打开「菜单配置」→ 只读展示全部一级菜单及二级菜单（含 landing 落地、图标）→ 无编辑控件。
  - 正常流：超管打开「角色 > 编辑 > 菜单权限」→ 树状勾选（与配置页同源）→ 保存 → 该角色侧边栏按勾选显示。
  - 边界：历史已保存的 MenuConfig 覆盖记录（如隐藏 Blog）→ 不再影响渲染，侧边栏按代码默认树显示。
  - 异常：无（只读页无写操作）。
  - 兼容：landing 落地、面包屑推导、i18n 全部保留（移除覆盖层后回归测试）。

## 3. 功能需求（FR）

### A. 菜单结构代码化（基线，无需改动）
- FR-001：菜单树（一级/二级、URL、landing、图标、badge、active）完全由代码导航配置（`pallastrade_admin_navigation.rb`）定义，作为唯一事实源。

### B. 菜单配置页只读可视化
- FR-002：「菜单配置」页（Settings > 菜单配置）改为**只读导航树展示**：展示全部一级菜单 + 二级菜单（含 landing 落地、图标、当前位置），**无任何编辑控件**（无显隐 checkbox、无改名/排序输入、无自定义项）。
- FR-003：移除「新增自定义菜单项」能力：`_custom_item_fields` 不再渲染、`rebuild_configs` 不再写 custom 记录、相关入口/文案移除。
- FR-004：移除「显隐/改名/排序」写入：`items` 参数不再处理，历史覆盖记录不再应用于渲染。
- FR-005：移除本次"删除菜单/添加二级菜单"需求（方向性撤销）：结构增删一律走代码。

### C. 权限配置依据（可视化树）
- FR-006：角色「菜单权限」tab（P2 已实现）保持**树状勾选**，数据源与菜单配置页为**同一导航树**（单一事实源），作为权限配置依据。
- FR-007：菜单配置页与 Roles 菜单权限页共享同一树渲染组件/数据来源，保证"看到的 = 可勾选的"。

### D. 数据与渲染清理
- FR-008：导航渲染层**停用 MenuConfig 覆盖层合并**（`apply_menu_config_overrides`/`build_effective_nav` 覆盖部分不再生效），侧边栏严格按代码配置渲染。
- FR-009：`pallastrade_menu_configs` 表与 `MenuConfig` 模型**保留不删**（避免破坏性迁移与历史数据兼容），仅停用写入与渲染引用；`nav:validate` 保留覆盖 key 校验逻辑但不再有写入来源（或按实现移除）。

## 4. 非功能需求（NFR）

- 安全：只读页无写操作，杜绝结构误改；权限仍由角色体系控制。
- 兼容：landing 落地、active 高亮、badge、面包屑推导、i18n 全部保留（移除覆盖层后回归）。
- 可维护：菜单结构单一事实源 = 代码导航配置；可视化只做展示，零状态。
- 可测试：移除覆盖层后渲染回归（默认树 = 侧边栏）；权限勾选回归。
- 性能：只读页单次导航树遍历渲染，无额外 DB 查询；渲染层去掉覆盖合并后更快。

## 5. 验收标准（AC，与测试一一映射）

- AC-001 ← FR-002：菜单配置页只读展示完整菜单树（一级 + 二级，含 landing 落地与图标），页面无编辑控件（无 checkbox / 输入框 / 保存按钮）。
- AC-002 ← FR-003：菜单配置页无「自定义菜单项」区块与新增入口；`MenuConfigsController` 无写路由（仅 GET index）。
- AC-003 ← FR-004/008：历史 MenuConfig 覆盖记录（含 hidden/label/position/custom）**不影响**侧边栏渲染，侧边栏 = 代码默认树。
- AC-004 ← FR-005：无"删除菜单/添加二级菜单"入口（需求撤销）。
- AC-005 ← FR-006/007：Roles 菜单权限仍为树状勾选且与菜单配置页同一结构（抽查 Orders 下二级项一致）；保存后该角色侧边栏按勾选显示。
- AC-006 ← NFR/兼容：移除覆盖层后 landing 落地与面包屑仍正确（抽查 Orders 落地、Developers > API Keys 面包屑）；`nav:validate` 通过。

## 7. 技术影响

- **Admin 视图**：
  - `views/pallastrade/admin/menu_configs/index.html.erb`：改为只读树渲染（去掉 form/checkbox/输入框/自定义区块/保存按钮）。
  - 删除 `views/pallastrade/admin/menu_configs/_custom_item_fields.html.erb`（不再引用）。
- **Admin 控制器/路由**：
  - `menu_configs_controller.rb`：删除 `update`/`rebuild_configs`/`items_params`/`custom_items_params`；仅保留 `index` + `load_menu_config_context`（只读数据）。
  - `config/routes.rb`：移除 `post 'menu_configs'`（保留 `resources :menu_configs, only: [:index]` 或等价 GET）。
- **导航渲染**：
  - `navigation_helper.rb`：`build_effective_nav` 移除覆盖层合并（或直接返回原 nav）；删除 `apply_menu_config_overrides`/`find_nav_item`（若不再被引用）。
- **Core 模型**：`menu_config.rb` 保留（不删表），仅停用写入来源；如需彻底清理历史记录可加一次性 seed/迁移（可选）。
- **i18n**：`admin.menu_configs.*` 文案收敛为只读说明（移除 editable 相关文案）；en + zh-CN。
- **Spec**：更新 `spec/requests/pallastrade/admin/menu_config_spec.rb`（改为只读断言：GET 200 + 无编辑控件 + 覆盖不生效）；`roles_permissions_spec.rb` 保留（菜单权限回归）。
- **无 DB 迁移（除非清理数据）；无 API 变更**；storefront/platform 不涉及。
- 影响面：`harness affected --base origin/main` 实施时输出。
