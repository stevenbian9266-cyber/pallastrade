## 1. 背景与目标

- **一句话需求原文**：后台可视化菜单配置模块 + 与权限系统关联；修复无法设置角色 permission；权限分为菜单权限、数据权限、功能权限。
- **背景**：
  1. 管理后台菜单完全由代码配置文件声明（`pallastrade_admin_navigation.rb` + `Item#visible?`），**无运行时可视化配置**——改菜单/显隐/排序/改名必须改代码 + 部署。
  2. `PallasTrade::Role` 只有 `name` 字段；角色→权限映射硬编码在 `backend/config/initializers/pallastrade.rb`（仅 `:default` → DefaultCustomer、`:admin` → SuperUser），**Roles 编辑页只有 name 输入框，无法设置角色权限**。
  3. 现有权限粒度只有代码级 PermissionSets（`can :manage, Model` 粗粒度），**没有 菜单权限/数据权限/功能权限 的分类体系**。
  4. 菜单可见性目前仅靠 `if: -> { can?(:manage, Model) }` 过滤，**未与角色权限体系关联**。
- **目标**：
  1. 后台**可视化菜单配置模块**：显隐/排序/改名/新增自定义菜单项，DB 存储，即时生效。
  2. 菜单配置与**权限系统关联**：菜单可见性由角色「菜单权限」决定。
  3. **角色权限可配置**：Roles 编辑页新增权限矩阵，可设置每个角色的 菜单权限 / 功能权限 / 数据权限。
  4. **权限体系重构**：DB 角色权限完全取代代码级 PermissionSets，并迁移现有配置。
- **成功指标**：
  - 管理员在后台 5 分钟内完成菜单显隐/排序/改名并即时生效（无需改代码/部署）。
  - 新建角色 → 勾选权限 → 登录验证生效，全程无代码改动。
  - 现有 `admin`（SuperUser）与 `default` 角色行为在迁移后零回归。

## 2. 用户故事 / 场景

- 作为**超管**，我希望在后台可视化配置整棵菜单树（显隐/排序/改名/新增自定义链接），以便无需发版即可调整导航。
- 作为**超管**，我希望在角色编辑页勾选权限（菜单/功能/数据），以便为不同角色分配差异化的访问能力。
- 作为**客服角色**，我希望只能看到订单相关菜单且只能查看（不能删除/导出），以便最小授权。
- 作为**区域主管**，我希望数据权限限定为"本人/本店铺/本渠道"，以便只看自己管辖的数据。
- 场景列表：
  - 正常流：超管进入「菜单配置」→ 全局模式下隐藏 Blog、调整 Orders 排序 → 保存 → 刷新即时生效。
  - 正常流：超管进入「角色 > 编辑」→ 功能权限勾选 `orders:read` → 该角色用户只能看订单不能改。
  - 正常流：店铺 A 在「菜单配置」店铺模式下把某菜单改名 → 仅店铺 A 生效。
  - 边界：未配置任何菜单权限的角色 → 按默认树全量显示（向后兼容）。
  - 异常：数据权限自定义条件表达式非法 → 保存时校验报错，拒绝入库。
  - 异常：删除已被角色菜单权限引用的自定义菜单项 → 级联清理角色权限引用，提示确认。

## 3. 功能需求（FR）

### A. 可视化菜单配置模块
- FR-001：后台新增「菜单配置」模块（入口：Settings > 菜单配置），可视化展示**整棵导航树**。
- FR-002：支持**全局模式 + 店铺覆盖模式**：全局为默认配置；店铺模式下可覆盖显隐/排序/改名/自定义项，仅对当前店铺生效。
- FR-003：每个导航项可：**显示/隐藏**（checkbox）、**改名**（label 覆盖）、**排序**（拖拽/上下移）。
- FR-004：支持**新增自定义菜单项**：label、URL（站内/外链）、图标、父级、排序、新窗口打开；可编辑/删除。
- FR-005：保存即时生效（DB 读取，无需重启/部署）；菜单配置变更记录审计日志。
- FR-006：配置基于现有导航配置树（`pallastrade_admin_navigation.rb`）作为默认基线，**覆盖层叠加**，不破坏 landing/tabs/i18n/面包屑推导。

### B. 角色权限体系（菜单权限 / 功能权限 / 数据权限）
- FR-007：`Role` 可配置权限（Roles 编辑页新增「权限」区，三个 tab：菜单权限 / 功能权限 / 数据权限），修复"无法设置角色 permission"。
- FR-008：**菜单权限**：树状勾选每个导航项（含子项），角色仅可见被授权的菜单项；未配置菜单权限的角色按默认树全量显示。
- FR-009：**功能权限**：资源 × 操作矩阵（read / create / update / destroy / export / manage），如 `orders:read`、`products:manage`；`manage` = 全部操作。
- FR-010：**数据权限**：资源 × 数据范围（`all` 全部 / `self` 仅本人创建 / `store` 按店铺 / `channel` 按渠道 / `custom` 自定义条件），作用于列表查询（`accessible_by`）。
- FR-011：权限生效规则：**DB 角色权限完全取代代码级 PermissionSets**；现有 `admin`（SuperUser）与 `default` 配置迁移为 DB 种子数据。
- FR-012：菜单权限与菜单配置联动：菜单项可见 =（菜单配置未隐藏）且（角色菜单权限允许）；功能权限不足时菜单项仍显示但操作被禁用（或按现有 can? 隐藏按钮）。

### C. 兼容与安全
- FR-013：`admin` 角色保留 SuperUser（全量菜单 + 全量功能 + 全量数据），迁移后零回归。
- FR-014：数据权限自定义条件使用**白名单表达式**（仅允许资源字段 + 简单比较/范围），禁止任意 Ruby 求值，防注入。
- FR-015：`nav:validate` 校验器扩展：菜单配置覆盖 key 必须存在于默认树（自定义项除外）；角色权限 resource 必须存在于权限注册表。

## 4. 非功能需求（NFR）

- 性能：菜单渲染合并覆盖层 + 权限过滤单次查询（N+1 防治）；全量菜单树渲染 < 200ms。
- 安全：自定义条件表达式白名单 + 参数化；权限变更即时生效并写审计。
- 兼容：现有 `if: -> { can? }` 导航过滤、面包屑推导、landing/tabs 全部保留；API 与 storefront 不受影响。
- 可维护：权限注册表（`PermissionRegistry`：resource → 可用操作 + 数据字段）单一事实源；菜单配置与导航配置解耦为「基线 + 覆盖层」。
- 可测试：权限判定纯函数化，spec 覆盖矩阵；`nav:validate` 扩展。

## 7. 技术影响

- **新建模型**（pallastrade_core）：`MenuConfig`（store_id 可空=全局、nav_key、覆盖字段、自定义项字段）、`RolePermission`（role_id、permission_type、resource、action、nav_key、scope、scope_value、custom_condition JSON）。
- **迁移**：`Role` 加 `has_many :role_permissions`；`pallastrade_role_permissions` / `pallastrade_menu_configs` 表；seed：现有 `admin`→SuperUser 全量、`default`→DefaultCustomer、并把 `PallasTrade.permissions.assign` 配置迁移为 DB 记录。
- **权限引擎**：`Ability#apply_permissions_from_sets` → 从 DB `role_permissions` 构建（保留 `pallastrade_admin?` 兼容）；新增 `PermissionRegistry`（resource 注册表 + 可用操作 + 数据字段）；新增菜单权限判定。
- **导航渲染**：`Navigation#visible_items` / helper 合并 `MenuConfig` 覆盖层 + 角色菜单权限过滤；`Navigation::Item` 支持覆盖 label/position/visible；渲染层支持自定义菜单项。
- **数据权限**：`accessible_by` 集成——各 controller 的 scope 按角色数据权限注入条件（self/store/channel/custom）。
- **Admin UI**：`pallastrade_admin` 新增 菜单配置 controller/views + 导航树渲染组件；`roles` 视图扩展权限矩阵（三 tab）。
- **校验器**：`nav:validate` 扩展（覆盖 key 存在性、权限 resource 存在性）。
- 影响面：`harness affected --base origin/main` 实施时输出。
