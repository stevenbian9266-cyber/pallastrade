## 1. 背景与目标

- **一句话需求原文**：优化：管理后台支付配置选项化（支付商 × 支付方式 → 前台入口）
- **背景（代码事实）**：
  - 后台支付管理现状 = `/admin/payment_methods`（`ResourceController` + `PreferencesConcern`），表单字段只有 `name` / `display_on` / `auto_capture` / `active` + provider preferences；**一条记录 = 一个支付商**，所以 Stripe 只能有一个前台入口，卡 / Apple Pay / Google Pay 无法分别开关。
  - 前台可用列表 `Order#collect_frontend_payment_methods` 过滤条件仅 `store + active + display_on + available_for_order?`。
  - `PallasTrade::PaymentMethod` 已有 `active` / `position` / `session_required?` / `source_required?` / `public_preferences`，可作为 Provider 载体直接复用（无需改表即可落 Option 于 `metadata.options`）。
- **目标**：把「支付商」与「前台入口」解耦——商家在后台能**按支付方式**（method）分别启用/停用/排序/命名，并立即反映到前台；凭证可体检、可脱敏。
- **成功指标**：
  1. 配置 Stripe 后，`card` / `apple_pay` / `google_pay` 可**独立**启停；停用后前台即时消失（不改代码、不重启）；
  2. 前台入口顺序 = 后台 `position`；
  3. 凭证在页面与 API 均为脱敏值；Test connection 给出明确结果（成功 / 失败原因）；
  4. 迁移零回归：未选项化的 provider 行为与今天完全一致。

### 1.1 本轮（2026-09-20 起：Stripe 厂商详情页定向优化）

- **触发**：运营实际使用反馈 —— 点「设置 → 支付方式 → Stripe」进入编辑页后，页面首屏是「厂商诊断卡 + 账户配置手填表单」，
  而真正想做的事（配 key → 测连接 → 逐种方式看/开关）散落在页面中下部；「厂商事实」与「本店决策」混在一起，无从下手。
- **本轮目标**：把 Stripe 的厂商详情页**定向**重排为「**先连接、再方式**」（Adyen / PayPal **不受影响**），并把这个页上的死重与杂音删掉。
- **成功指标**：
  1. 进入 Stripe 详情页，**首屏即为凭证与 [测试连接]**，上次体检结果就地可见（不再需往下翻到「支付方式」卡）；
  2. 页面上不再出现空的「配置指南」与「支付路由预览」两个无价值区块；
  3. 非 Stripe provider 的详情页与今天**逐像素一致**（同一 partial 集合、同一字段顺序）。
- **不在本轮（后续切片）**：方式列表按「Stripe 账户事实 ∩ 本地能力」四象限渲染、从 Stripe 同步已启用方式、
  去掉适用范围（市场/国家/Zone/币种）编辑 UI、`test_connection` 的真实远端探测、诊断卡自身收缩。

## 2. 用户故事 / 场景
- 作为**运营**，我希望关掉 Apple Pay 只保留卡支付，以便在钱包出问题时快速止损（不需发版）。
- 作为**技术/运营**，我希望新增一个 PayPal 支付商后能勾选它支持的方式并调整顺序，以便在不改代码的前提下上线新通道。
- 作为**管理员**，我希望看到凭证是否有效（Test connection），以便在上线前发现配置错误。
- 场景：正常（启用三种方式并按顺序展示）/ 边界（provider 无 options → 回落默认入口）/ 异常（凭证错误 → Test connection 失败原因；停用 provider → 全部入口消失，历史订单不受影响）。

## 3. 功能需求（FR）

- **FR-001　Provider 列表增强**：`/admin/payment_methods` 每行显示 provider 名称、类型、环境徽标、**已启用入口数**、以及「管理入口」入口。
- **FR-002　Provider 详情 · 「支付方式」页签**：以能力目录表呈现该 provider 支持的 method 列表：method 名（只读）、是否支持、**启用开关**、前台显示名、图标、排序、前端形态（只读）。
- **FR-003　启停即时生效**：启用/停用某 method → 前台列表随之变化，**无需改代码或重启**；停用后 `PaymentSessions::Start` 拒绝该 method（同源校验）。
- **FR-004　排序**：入口按 `position` 渲染，可在后台调整（复用既有 sortable 交互）。
- **FR-005　Test connection**：对 provider 执行一次凭证体检，返回明确结果（成功 / 失败原因：凭证错 / 域名未验证 / 商户号缺失 / 网络不可达），并记录最近一次结果。
- **FR-006　凭证脱敏**：页面与 admin API 一律只展示脱敏值（保留后 4 位），日志不落明文。
- **FR-007　零感迁移与 `optionized` 门控**：未选项化的历史 provider 在无 options 时回落为 1 个默认入口；一旦 `optionized = true`，`0 options` 即 **0 个前台入口**（不允许自动兜底）。
- **FR-008　停用/删除语义**：停用或删除 provider → 其全部入口从前台消失；**历史订单与支付记录不受影响**（不得级联删除）。
- **FR-009　僵尸记录清理**：清理 dev 环境的历史脏数据（重复 Check / StoreCredit / 测试记录，软删）。

#### 本轮新增（S1，2026-09-20）

- **FR-010　厂商页面分派（provider-driven page dispatch）**：新增 `PaymentMethod#provider_page_partial_name`（基类返回 `nil`）；
  `PallasTradeStripe::Gateway` 返回 `'pallastrade_stripe'`。`edit.html.erb` 在名称 `present?` 时渲染
  `payment_methods/provider_pages/<name>`，否则**沿用默认版面**（Adyen / PayPal / Check / StoreCredit 零回归）。
  沿用既有「provider 声明 partial 名」范式（`description_partial_name` / `custom_form_fields_partial_name` /
  `configuration_guide_partial_name`）与 `payments/new.html.erb` 的 `source_forms/#{method_type}` 分派惯例。
- **FR-011　Stripe 页「连接区」置顶**：Stripe 页首卡 = 凭证（`publishable_key` / `secret_key`，走既有
  `preference_fields` + `masked_password_preferences` 掩码回显）+ 环境（`environment`）+ **[测试连接] 按钮与
  最近一次结果**（结论 / 错误码 / 时间 / 脱敏消息）就近展示，数据源仍为 `metadata['last_test_connection']`。
  按钮沿用既有 Turbo 栈约定（`link_to` + `data: { turbo_method: :post }`，**非嵌套表单**）。
  默认版面的 `_options` 卡**保持现状**（按钮与结果不迁移，非 Stripe provider 零回归）。
- **FR-012　删除 Stripe 空配置指南**：删除 **0 字节**的 `configuration_guides/_pallastrade_stripe.html.erb` 与
  `PallasTradeStripe::Gateway#configuration_guide_partial_name`（Adyen 556B / PayPal 436B 的真实指南**不动**）。
- **FR-013　删除 P3-C 后台路由预览卡**：移除 `_provider_diagnostics` 内 `[data-testid="provider-routing-preview"]`
  区块、`PaymentsHelper#provider_routing_preview`、及对应 i18n 键（en + zh-CN 双向同步）与请求规格断言；
  **路由引擎全部保留**（`Payments::Routing::{Decide,Policy,Summary}` 与 `payment-routing-rspec` 不动）——
  移除的只是**后台展示面**（理由：跨厂商路由不属于「单厂商配置」页；其结论在订单上下文才有意义）。
- **FR-014　熔断卡折叠**：熔断卡改为可折叠（保留锚点 `#payment_method_breaker` 与全部软置灰/解除动作与指标），
  默认收起，降低常规配置时的视觉噪声。

## 4. 非功能需求（NFR）

- **兼容**：API 变更 additive（保留现有 `PaymentMethodSerializer` 字段）；老后台页面可继续工作。
- **安全**：凭证不出后端；Test connection 结果与凭证查看动作写审计。
- **样式**：遵循 B6-1 的 admin 设计 token 与密度（`data-admin-density`），禁止内联样式 / 硬编码色（AP-001/AP-006）。
- **i18n**：新增文案 en + zh 同步（后台 i18n 约定）。
- **性能**：入口查询不得引入 N+1（列表页按 provider 预载 options）。
- **样式（S1 补充）**：不新增内联样式 / 硬编码色；优先复用既有组件类（`card` / `card-header` / `badge` / `btn` /
  `form-select` / `form-text`）与设计 token；不直引 Tailwind 调色板做大面积主色/语义色；
  守护 `harness verify admin-theme-rspec`（token 集合、组件零直引、三 layout 的属性、WCAG AA 对比度）。
- **i18n（S1 补充）**：新增/删除键 en + zh-CN **双向键集相等**（CI 有 `spec/i18n/**` 覆盖率校验）；
  `off` / `on` / `yes` / `no` 这类会被 YAML 1.1 当布尔的**键名必须加引号**。
- **兼容（S1 补充）**：非 Stripe provider 页面**最终产物不变**（同一 partial 集合）；不新增路由、不改写路径。
