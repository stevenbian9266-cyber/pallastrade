# PRD-{YYYYMMDD}-{category}-{slug}

> **写作要求（强制 —— 不满足即打回重写）**
>
> 1. **本模板是下限，不是上限**。每节按真实事实填满，**禁止留占位符**（`<...>`、`待补充`、`TBD`）。
> 2. **篇幅**：新功能 ≥ 150 行 · 优化迭代 ≥ 120 行 · Bug 修复 ≥ 80 行。
> 3. **FR ↔ AC 双向完整**：每条 FR ≥ 1 条 AC；每条 AC 必须有**可执行的判定条件** + **测试落点（文件路径）**。
>    不允许用「人工看一下」充当验收。
> 4. **场景必须含边界与异常**：§2 的「类型」列至少各出现一次 **边界** 与 **异常**。
> 5. **证据先于结论**：§1.1 每条现象都要给证据（命令输出 / SQL 结果 / 代码位置 / 截图）；禁止「可能是 / 应该是」。
> 6. **写代码前这些节必须已存在**：§6 跨层搜索、§10 风险与回滚、§11 决策记录。
> 7. **可省略节**（仅 Bug 修复且确有理由时，须写「本节不适用：<原因>」）：§11 决策记录、§12 开放问题。
> 8. **收尾五处同时核对**：① 状态头 ② §9 勾选 ③ §13 变更记录 ④ `docs/prd/README.md` 索引 ⑤ REQ 头部引用。
