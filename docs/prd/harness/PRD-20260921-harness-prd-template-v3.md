### 1.2 根因

- 根因链：模板在 2026-09-21 的 6→14 节升级（提交 `64f29c38`）面向的是「把平台实际水位固化为强制结构」—— 固化的字段（现象+证据、根因、FR、NFR、AC、跨层、技术影响）全部偏向**后端/运营类需求** → **产品侧三要素（界面 / 交互 / 数据观测）缺位**；而「更详细」的抓手只落在**篇幅**（≥150/120/80 行）与**禁止占位符** → AI 写 PRD 时没有 UI/UX 的锚点节 → 界面与交互信息不进 PRD 或散落在 FR 自由文本 → 实施期再补、评审无依据（对应 E1/E2/E3）。
- 漂移链：`scenarios.json` 上一轮升级后未按生成器声明重跑 `eval-llm --generate` → `promptfoo/prompts/gs-013.txt` 停留旧契约（对应 E4）。

### 3.2 功能详述（逐 FR 行为规格）

#### FR-001 模板 17 节结构

- **触发与入口**：AI 收到一句话需求 → `harness prd new`；或按文档自查时的对照阅读
- **前置条件**：无；模板文件存在
- **主流程**：读模板 → 节序列 §0 摘要 → §1 背景与目标（1.1–1.4）→ §2 用户与场景（2.1–2.2）→ §3 功能需求（3.1–3.2）→ §4 界面规格（UI）→ §5 交互与体验（UX）→ §6 数据与埋点 → §7 NFR → §8 AC → §9 跨层搜索 → §10 技术影响 → §11 测试计划 → §12 文档同步清单 → §13 风险与回滚（13.1–13.3）→ §14 决策记录 → §15 开放问题 → §16 变更记录
- **分支与边界**：纯后端需求 → §4/§5/§6 写「不适用 + 理由」；Bug 修复 → §6/§14/§15 可整节省略（写「本节不适用：<原因>」）
- **异常处理**：节缺失/重号 → 守卫测试报具体节号，AI 按报告修复
- **后置状态**：`harness prd new` 复制的是新结构；已有 PRD 不受影响
- **权限**：任一 AI 助手可写；守卫不可被跳过（除非同步降档并经确认）
- **验收映射**：AC-001

#### FR-002 功能详述八要件

- **触发与入口**：撰写 §3.2 每个 P0 FR 的详述小节时
- **前置条件**：§3.1 总表已列出 FR 编号与优先级
- **主流程**：按下述八键逐项填写（不涉及写「无」或「不适用」）：触发与入口 / 前置条件 / 主流程（编号步骤）/ 分支与边界 / 异常处理 / 后置状态 / 权限 / 验收映射（AC 编号）
- **分支与边界**：P1/P2 FR 至少填写「触发 / 主流程 / 异常」三项；既有能力引用需给文件路径
- **异常处理**：缺失键 → 守卫按关键词断言失败（如缺「异常处理」）
- **后置状态**：每条 P0 FR 均可被实现者按详述直接编码，无需回读自由文本
- **权限**：同 FR-001
- **验收映射**：AC-002

#### FR-003 界面规格（UI）五件套

- **触发与入口**：需求含界面（storefront/admin/dashboard）时填写
- **前置条件**：跨层搜索已定位可复用组件（§9）
- **主流程**：① 页面与路由清单（页面 / 路由 / 新增改动 / 归属）② 组件与复用决策（组件 / 复用·改造·新增 / 现有路径或新建位置）③ 状态矩阵（loading / empty / error / success / 禁用 逐行给出触发与展示）④ 视觉与设计 token（用途 / token 引用；禁止硬编码色值字号间距）⑤ 文案与 i18n（元素 / 中文 / locale key / 英文）
- **分支与边界**：无设计稿时以现有组件库与邻近页面为视觉基线，推断项登记 §15
- **异常处理**：不涉及界面 → 整节「不适用 + 理由」；写了界面但状态矩阵缺行 → 评审退回
- **后置状态**：实现者可直接将 token/文案 key 映射到代码
- **权限**：同 FR-001
- **验收映射**：AC-003

#### FR-004 交互与体验（UX）四件套

- **触发与入口**：需求含用户操作路径（新建入口、模态、多步流程、支付/结账类）时填写
- **前置条件**：场景表（§2.2）已定稿
- **主流程**：① 核心操作流程 step-by-step（覆盖正常路径 + ≥1 条异常路径）② 反馈机制（操作 / 反馈形式 / 成功表现 / 失败表现 / 防重复或幂等）③ 边界与异常体验（超时 / 并发冲突 / 权限不足 / 离线 / 空数据 → 用户可见表现 + 恢复路径 + 证据形式）④ 无障碍与键盘（焦点管理 / 键盘可达性 / aria）
- **分支与边界**：反馈机制必须显式回答「防重复提交」；失败路径遵守 AP-009（降级 UI 不得静默吞错、不得触发死循环）
- **异常处理**：不涉及交互 → 整节「不适用 + 理由」
- **后置状态**：UX 验收（含失败路径）有明确证据形式（截图 / DOM / 组件测试）
- **权限**：同 FR-001
- **验收映射**：AC-004

#### FR-005 数据与埋点

- **触发与入口**：需求涉及可观测指标、事件上报、运营数据时填写
- **前置条件**：§1.3 成功指标已定义
- **主流程**：① 指标口径表（指标 / 定义或公式（分子分母）/ 数据来源 / 观测方式）② 事件清单（事件名 / 触发时机 / 关键属性 / 落点；属性禁 PII，参照既有 catalog_events 白名单机制）
- **分支与边界**：分母为 0 或不可判定 → 显式写「不可判定」与返回语义，不得编造 0
- **异常处理**：不涉及 → 整节「不适用 + 理由」
- **后置状态**：指标可复算、事件可对账
- **权限**：同 FR-001
- **验收映射**：AC-005

#### FR-006 写作要求升级

- **触发与入口**：任何按模板扩充 PRD 的写作过程
- **前置条件**：模板为唯一权威
- **主流程**：写作要求块载明：① 篇幅下限 新功能 ≥200 / 优化迭代 ≥150 / Bug 修复 ≥100 行 ② 禁止占位符（`<...>` / 待补充 / TBD）③ FR↔AC 双向完整 + 测试落点 ④ 场景含边界与异常 ⑤ 证据先于结论 ⑥ 写码前必备节 §9/§13/§14 ⑦ 节级豁免规则 ⑧ 收尾五处核对（①状态头 ②§12 勾选 ③§16 变更记录 ④README 索引 ⑤REQ 引用）⑨ 示例注释纪律：模板示例一律置 HTML 注释内（`prd verify` 忽略注释，避免 phantom AC/FR 被计入）
- **分支与边界**：Bug 修复可省略 §6/§14/§15；豁免须写原因
- **异常处理**：留占位符或短于下限 → 评审打回（GS-013 mustNotDo 同步载明）
- **后置状态**：「更详细」= 结构（17 节全填）+ 深度（八要件）+ 篇幅（三档下限），三层可检
- **权限**：同 FR-001
- **验收映射**：AC-006

#### FR-007 结构守卫

- **触发与入口**：`harness verify repo-guards-test --task <TASK-ID>`；CI `node --test` 同一文件
- **前置条件**：`harness.config.mjs` 的 repo-guards-test 命令数组注册本文件
- **主流程**：解析 `docs/prd/_TEMPLATE.md` → 断言 §0–§16 序列连续且无重复 → 断言 §3.2/§4/§5/§6 子节与关键词 → 断言写作要求（三档下限 / 豁免 / 注释纪律 / 必备节编号）→ 跨文件断言（SKILL §2.3 清单、GS-013 description/mustDo、promptfoo gs-013.txt 契约）→ 元数据断言（目标用户 / 界面影响）
- **分支与边界**：断言基于标题正则与关键词，不引入脆弱全文快照；豁免句（不适用 + 理由）为合法内容
- **异常处理**：任一断言失败 → 输出「缺哪节/哪个子节/哪处不一致」；修复后重跑
- **后置状态**：模板结构成为 CI 可执行的契约；后续模板演进必须同步改守卫与知识文件
- **权限**：同 FR-001
