## PT-PVT-002: Storefront 完整购物链路 ✅

### 操作过程

1. Seed 产品、Stock、Payment Method、Shipping Method
2. 通过 API 完成: Products → Cart → Add Item
3. 通过 Admin 后台可视化管理

### API 链路验证

| 端点 | 方法 | 状态码 | 备注 |
|------|------|--------|------|
| `/api/v3/store/products` | GET | 200 | 返回产品列表 |
| `/api/v3/store/carts` | POST | 201 | 创建购物车 |
| `/api/v3/store/carts/:id/items` | POST | 201 | 添加商品 |
| `/api/v3/store/carts/:id` | PATCH | 200 | 更新地址/email |
| `/api/v3/store/carts/:id/complete` | POST | — | 待验证 |

### 发现的关键问题

#### 🔴 Blocking: `Spree::Product.available()` 返回空

**根因**: Spree 5.6.0.rc1 新增 `spree_product_publications` 表。产品 seed 后不会自动出现在 storefront API，必须显式创建 `ProductPublication` 关联 channel。

**修复**:
```ruby
Spree::Product.all.each do |p|
  Spree::ProductPublication.create!(
    product: p,
    channel: Spree::Channel.find(1),  # "Online Store"
    published_at: Time.current
  )
end
```

**影响**: 所有 Store API v3 的产品查询都依赖此机制。1.0 阶段需要将此步骤纳入标准 seed 流程。

#### 🔑 认证区分

| Key 类型 | 前缀 | 用途 | 存储方式 |
|----------|------|------|---------|
| Publishable | `pk_` | Store API (前端公开) | 明文 token |
| Secret | `sk_` | Admin API (后端私密) | HMAC-SHA256 digest |

- Store API 仅接受 `pk_` 密钥，`sk_` 返回 401
- 请求需 `X-Spree-Token` header（不是 `X-Spree-Order-Token`）
- 请求需 `X-Spree-Api-Key` header

## PT-PVT-004: Namespace 重命名评估 ⚠️

### 状态: 受限——预构建 Docker 镜像不含源码

**当前环境**: `ghcr.io/spree/spree:latest` 预构建 Docker 镜像
**实际问题**: 所有 Spree gem 安装在容器内 `/usr/local/bundle/`，无法在宿主机直接编辑

### 规模评估 (容器内统计数据)

| gem | `Spree::Core` 引用文件数 |
|-----|--------------------------|
| spree_core | ~9 个文件 |
| spree_api | 待 fork 后统计 |
| spree_admin | 待 fork 后统计 |
| spree_emails | 待 fork 后统计 |

**关键文件**:
- `engine.rb` — 引擎注册与命名空间顶层定义
- `routes.rb` — 路由命名空间
- `*_factory.rb` (testing) — 测试工厂类
- `controller_requests.rb` — 测试辅助

### 1.0 阶段建议方案

1. Fork 全部 Spree gem 源码到 `pallastrade/` 目录
2. 使用 `sed`/脚本批量替换 `Spree::Core` → `PallasTrade::Core`
3. 修改 Gemfile 使用 `path:` 替代 gem 依赖
4. 自行构建 Docker 镜像
5. 运行全量测试，逐个修复

**预期工作量**: 3-5 天（与原始预估一致）
